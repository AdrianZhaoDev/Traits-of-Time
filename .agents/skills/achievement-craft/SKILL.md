# 成就系统制作指南 (achievement-craft)

本技能专门用于《时空词条：历史重开模拟器》（Traits of Time）中**现代词条 $\times$ 朝代历史时局**交互成就的设计、文案打磨与配置落地。

---

## 一、 核心定位与三大心理触发器 (Core Psychology)

成就用于记录真实经历，并提供继续探索的线索。名称应易懂、可区分；短评补充评价，不重讲事件全过程。

1. **趣味与分享**：保留事件原有的反差，不为每项强塞梗、夸大疗效或编造人物反应。死亡和灾难不拿受害者开玩笑。
2. **实力与稀有度**：用真实条件区分常见经历与困难成果，不能把稀有度写成不存在的身份、奖励或历史影响。
3. **收集与探索**：保持N/R/SR/SSR阶梯与名称区分，让玩家知道自己完成了什么；文案轻松自然优先，不要求威风称号或“神评级金句”。

---

## 二、 单词条单朝代【10个成就】黄金定额规范

每个现代词条（卡牌）进入一个特定朝代时，成就库数量**严格限定为恰好 10 个**，不多不少。10 个成就必须按稀有度与定位进行黄金比例切分：

| 稀有度 | 配额数量 | 定位与心理映射 | 对应 Category | Priority 权重区间 | 解锁门槛特征 |
| :--- | :---: | :--- | :--- | :---: | :--- |
| **N 级 (常见)** | **3 个** | **日常尝试、小误会、常见收获或意外**<br>名称好懂，短评自然；死亡经历克制记录，不拿受害者制造笑点。 | `anecdote` (奇物轶事) | 20 ~ 29 | 拿到道具后的摸索、日常尝试或误会，以实际条件为准。 |
| **R 级 (实用)** | **3 个** | **解决局部困难、发挥物品的实际用途**<br>写清具体得失，不把有限帮助夸成必胜或万能。 | `anecdote` / `milestone` | 30 ~ 49 | 度过特定困难、经营收获或帮助他人，必须有对应分支支持。 |
| **SR 级 (实力/名望)** | **3 个** | **完成困难检定或专属事业**<br>对人物、地方或历史事件的影响，只写到对应分支能够证明的程度。 | `milestone` (时代里程碑) | 60 ~ 79 | 历史事件中的实际贡献、官府认可或地方声望，以配置为准。 |
| **SSR 级 (少见成果)** | **1 个** | **苛刻条件下的难得经历或事业成果**<br>不靠神迹、夸大的历史评价或强造金句撑起稀有度。 | `milestone` 或 `life` | 80 ~ 95 | 四维联合判定、低概率分支或复合条件，以实际配置为准。 |

## 三、文案风格：自然的名称与一句短评

遵守 [`Doc/文案设计与风格规范.md`](../../../Doc/文案设计与风格规范.md)。先顺口，再精简；不模仿具体句子，不设固定字数或单行要求。

1. **名称**：准确、好懂且能区分不同成就；不硬凑四字，不为梗点发明原事件没有的事实。
2. **短评**：通常一句自然的短话，补充评价而非复述事件、选项和结果。允许平实、遗憾或紧张，不强制反转、吐槽和俏皮结尾。
3. **事实核验**：先读完整condition和对应事件分支；物品实际能力、成功失败、尚未确定、死亡与事业中断不能混写。
4. **组合检查**：名称、稀有度与分类由界面组合，text不再手写一套勋章前缀；检查手机实际宽度和连续阅读效果。

## 四、 研发落地配置规范 (JSON Schema 规范)

当前数据引擎中，`achievements.json` 的标准结构如下：

```json
{
  "id": "A_MOD_{ITEM}_{KEY}",
  "name": "成就名称",
  "text": "对这段真实经历的一句自然短评。",
  "condition": {
    "op": "all",
    "conditions": [
      {
        "op": "has",
        "collection": "cards",
        "id": "CARD_MODERN_{ITEM}"
      },
      {
        "op": "has",
        "collection": "flags",
        "id": "F_MOD_{ITEM}_{KEY}"
      }
    ]
  },
  "priority": 70,
  "category": "milestone"
}
```

稀有度和分类由现有priority/category映射给界面，不在text中重复写名称或勋章。纯文案修订保留ID、条件、权重和分类；改名后同步玩家可见引用。

## 五、 制作自查清单 (Checklist)

每次为一个词条制作朝代成就时，必须逐项核对：
- [ ] 数量是否严格等于 **10 个**？
- [ ] 是否具备 **3 个 N 级、3 个 R 级、3 个 SR 级、1 个 SSR 级**？
- [ ] 名称是否好懂且可区分，短评是否顺口、准确并避免复述事件？
- [ ] 是否与当朝历史大事件（天灾、战乱、名将重臣、疫病）紧密融合？
- [ ] 是否至少有 1 个成就属于**残壳第二春/暮年价值**？
- [ ] 失败或认知误区是否与真实分支相符，死亡灾难是否保持分寸？
- [ ] Priority 权重是否符合三轨终局原则（未违规占用最高级主身份人生终局）？
