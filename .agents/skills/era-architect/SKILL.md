# 朝代全景架构师 (era-architect)

本技能专用于《时空词条：历史重开模拟器》（Traits of Time）的**纯原生历史时代包（Era Pack）全景构建**。
本技能负责打造一个**无需任何现代道具即可自成一体、深厚宏大、充满命运交织与阶层浮沉的历史重开舞台**。
（后续的现代道具卡由 `modern-relic-craft` 技能在本作交付的时代底座上进行二次插桩）。

---

## 一、 核心架构原则：状态驱动演化模型 (State-Evolving Matrix)

玩家不是在被动接受流水账随机事件，而是**由“个人长期发展主线”与“外部时代背景事件”动态交织演化**：

```
触发事件 = f(当前年龄, 身份阶层, 四维属性, 财富水平, 长期志业标记, 历史年份)
```

1. **宏大事件库容量与动态稀释率**：
   * 每个朝代剧本必须拥有 **100+ 个以上的背景事件池**（涵盖宏大史实、阶层浮沉、市井百态、突发天灾）；
   * **单局调度**：3~15 个重点历史遭遇可作为体验采样目标，不是整个人生所有事件的上限；随机、自动、历史与链节点可继续按实际年岁发生。

2. **长期跨年志业体系（Directional Chains）**：
   * 通过条件与选项开启长期方向，如科举学习、军务、营缮、商贸、行医；成年人方向须有年龄与身份前提，少年学习可以另设门槛。
   * 节点 `after_years` 相对链启动年计算；节点效果才产生明确的成长、开销或奖励，不存在隐含的每年自动加成。配置成本、检定、失败及主动退路，不保证短期完成即获高官。
   * `interrupt_condition` 只在实际状态满足时中断；历史事件造成的局部后果须显式写入状态，不能只因年份到达就永久中断所有人。中断不自动扣资产或抹去已取得的能力，额外后果须由内容明确表达。
   * 启动门槛使用 `has` 的 `active_chains` 与 `completed_chains` 排除活跃或已完成的同链，并确保中断原因已消除；`STARTED` 标记只记录曾启动，不是永久锁。中断实例不续跑，重开是从起点建立新实例，已获得的属性与能力保留。
   * 整个人生严格只有 1–5 次成功的重大剧情选择，原生时代和未来现代词条共享同一结构：恰一次开局方向、至多一次随机事业转向、至多两次事业链终点、至多一次重大历史抉择。所有开局候选必须先于任何死亡给出方向选择，幼年为家人安排或学习取向，每个年龄、贫富起点至少有两条可用且不同的方向。阶段检定不是选择；拒绝的命令不计数，手动暂停、继续和放弃事业是可选控制，不是强制剧情选择。
   * 随机事业入口共用 `F_LIFE_DIRECTION_TURN_USED`，历史重大抉择共用 `F_LIFE_HISTORICAL_TURN_USED`：入口检查未使用，成功选择的每条路径在阶段前写入标记；开局及转向每次至多启动一条链，其他事件不得启动链，中途节点不设选择。链终点保留身份门槛，无法晋级时也要有至少两条实质不同且不降级的后路。每次抉择都应有趣或有挑战，交代投入、检定、风险与能被后续条件、收益或结局观察到的长期分歧，不能只给是/否或属性 +1。
   * 低影响日常和已授权的事业进展不展示菜单；需要不确定性时以 `automatic.outcome.next_stage_id` 接既有真实 D20 阶段，按属性、自然 1/20 与结果效果结算并保存日志、供恢复与回放。不得将自动阶段说成 `--auto` 代选或伪称分支等概率；不自动支付未授权的大额成本、启动事业或改换重大身份，也不将危险主动行为强加给玩家。低影响失败宜为有限损失，不能靠提高死亡率减少选择。人生只在死亡时结束，成就不授予主动结束资格。
   * 海贸各入口需财力至少 3，启动一次预付 3（原起步 2 加次年 1）；中途自动进展不再扣费，失败、中断或手动退出均不退已付投入。失败和灾害保留已得成长，原中断实例不续跑；仅转向机会未使用且条件允许时可重新起步，不强塞新事业。

3. **阶层与贫富状态的动态分流（穷有穷的劫，富有富的难）**：
   * 对贫富、体质、能力、身份等状态设计明确的准入门槛；也可保留适用范围清楚的通用日常事件。
   * **低谷困厄池（穷困/体弱专属）**：
     * 条件：`wealth <= 1` 或 `physique <= 2`；
     * 事件：拒绝苦难说教或平淡琐事，以接地气黑色幽默与市井自嘲呈现（如“锅底朝天喝西北风”、“蹭邻居烤火被当成门神”）；困境事件同样要有趣味与意外转机。
   * **高位危机与大势抉择池（巨富/高官/名士专属）**：
     * 条件：`wealth >= 6` 或 `prestige >= 6` 或特定高阶身份；
     * 事件：体验大明上层的魔幻日常与高维博弈（朝廷大摊派、东厂上门借银、巡抚深夜推演、被当大腿抱住）；文案充满荒诞戏剧感与凡尔赛幽默。
   * **纯随机/黑天鹅事件池（对标 lifeRestart 脑洞与奇遇）**：
     * 全面引入奇人异事、市井捡漏、摸鱼神技、意外暴富等强反馈事件。文字单句击穿，拒绝流水账。
     * 使用已有 `trigger_probability`、权重、冷却和次数限制表达偶遇、暴雨等随机触发；事件阶段的真实 D20 检定可供自动事件或选择路线使用，不是额外的触发门槛。

## 二、 朝代内容包（Era Pack）标准构成规范

构建完整朝代原生包（如 `ming_end`、`qin_han`、`tang_glory`）时，以真实 Schema 和引擎为准，保留仍有意义的原生 ID 及其引用；文案必须严格遵守《Doc/文案设计与风格规范.md》（全面对标 VickScarlet/lifeRestart：极简单句击穿、幽默脑洞、反转爽感，坚决铲除“老汉喝水、补屋、闲聊”等居委会流水账）。历史大事件保持客观荒诞与身不由己，严禁民族蔑称与血腥细节。

| 资产文件 | 最低配置规范 | 核心职责与设计要点 |
| :--- | :--- | :--- |
| **`era.json`** | 1 个时代定义 | 定义起始年、历史调度终点年、纪年规则、年龄身份晋升线（`age_transitions`）。 |
| **`rules.json`** | 1 套核心规则 | `events.per_year: 1` 是随机事件年度上限，并非每年必有选择；历史和链节点另行调度，事件也可自动执行。`chains.max_active: 2` 限制同时活跃链。 |
| **`castes.json` & `regions.json`** | 3~5 阶层 / 3~5 地区 | 军户、流民、士绅等原生身份与地域禀赋。 |
| **`events.json`** | **100+ 背景事件目标** | 不含现代内容；覆盖历史、市井和状态分流。长线链节点单独统计，不把选项和阶段算成事件。 |
| **`chains.json`** | 多条跨年长期任务 | 用相对启动年的节点、明确的选择成本、检定、退路和状态中断构成长期方向。 |
| **`achievements.json`** | 原生结局与成就 | 区分死亡终局状态判定的人生结果与已获得的事业里程碑、轶事；成就仅记录成果，不提前结束人生。 |
| **`deaths.json`** | 多种原生死因 | 区分战乱、疫病、饥困、寿终等情境；生产开局必须先有方向选择，通用引擎可用零选择直接死亡的独立夹具验证终局。 |

## 三、 标准化制作工作流 (3 阶段)

### 第一阶段：时代历史年表与发展大线策划 (Blueprint)
1. 梳理时代历史窗口（如崇祯朝 1628–1645），列出**核心历史重大节点年表**（杜绝大段时间空档，每 1~2 年均有历史锚点）；
2. 提炼本时代的 **5~6 个核心长期志业方向**（文治、武略、营缮、商贸、救民、潜修）；
3. 设定贫困、富贵、官身、草莽四大阶层的状态切片边界。

### 第二阶段：批量资产构建与门槛矩阵落位 (Assembly)
1. **编写 `chains.json`**：先立志业骨架，定义年限与打断逻辑；
2. **编写 `events.json`**：
   * 编写开局起步事件；
   * 编写跨越全历史窗口的史实大事件；
   * 在事件根级 `condition` 使用已有条件语法，例如 `{"op":"compare","field":"wealth","comparator":"lte","value":1}`；地区、门第等用 `op: is`，组合用 `all / any / not`。禁止虚构 `attribute_gte`、`attribute_lte` 字段；
   * 需要不确定结果时使用已有 D20 阶段：自动事件以 `outcome.next_stage_id` 进入，选择路线以其阶段进入；配置符合事件条件的成功与失败后果，不把随机触发或等概率代选伪装成检定；
3. **编写 `achievements.json`**：区分终局状态与过程里程碑，不让曾经的财富覆盖最终人生状态。

### 第三阶段：全量工程验收与多策略仿真 (Verification)
1. 运行内容校验：`npm run validate:content -- --content assets/resources/data/<era_id>`
2. 运行项目实际声明的完整测试命令（当前为 `npx vitest run`）；
3. 运行自动化仿真（`tools/simulate.ts`）：
   * normal、cautious、risky 和优先事业发展策略各跑至少 100 个完整人生种子，逐局统计成功剧情选择并检查最小值至少 1、最大值至多 5；开局确认、自动阶段和可选控制不计入剧情选择。另报告分层样本与 P50/P90、早死率，核对各年龄及地区门第组合至少两个可用开局方向、链可达与选择的长期分歧，抽查自动 D20 的不同结果及恢复回放；时长须另行真人实测。
   * 检查老死与暴毙比例，确保不存在单一死因垄断；
   * 检查高阶与低谷成就的分布，证明状态演化分流真实生效。
4. 验收合格后，宣布**原生朝代底座构建完毕**，可正式移交 `modern-relic-craft` 接入现代道具切片。
