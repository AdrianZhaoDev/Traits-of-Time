# 04-UI与程序动效实现

## 使用方式

将代码块完整复制给能访问本项目的编程／设计 AI，仅在另行委托本阶段实施时执行。本轮只覆盖文档，不改代码，不代表完成客户端验收。[整体 UI 主规范](../../UI整体风格方案.md)定义已获选 A，[动效配套规范](../../动效与微交互制作规范.md)定义短响应；不再选择风格。

你负责第四阶段：将A与真实获批素材实现为可操作局外UI及程序动效，不是静态整页截图。输入为01共享清单、02 A Canvas样板/主规范链接、03实际已验收资源、08末尾程序动效提示词。计划资源不伪装成已存在；可选装饰缺失不要求新增玩法或假数据。

执行顺序：首页→身份/家当→成就/统计/声音→管理四页/详情→终局。

4. 实际Canvas缩放后正文约16 CSS px以上，辅助字底线12、重要警告目标13–14；正常字对比4.5:1、大字及有意义边界3:1。点击至少44 CSS px、间距8 CSS px，逻辑阈值ceil(44*750/实际CanvasCSS宽度)，360→92、390→85；750不是CSS/DPR。背景等比适配、注意安全区；短屏先减插画和空隙，再滚动，不缩文字/控件。长文完整换行，长列表可滚；空态只显示真实无数据状态。
5. 声音三个通道保留拖动/加减/静音恢复及0值语义；管理保留真实事业退出成本/风险；选卡仅换选、不点击同卡取消，不接SFX-07。真实结果/下一步立即可见可操作，不强制1.5–2.4秒滚轴/翻牌，不由动画生成随机结果、提交状态或消费游戏PRNG。
6. 统一短动效：按下80–120ms，视觉颜色约160ms；入场160–220ms、退场100–160ms、选中120–160ms；小位移最多6 CSS px。进入、退出和状态过渡统一使用A曲线 cubic-bezier(0.2,0.7,0.3,1)，高频导航可直接切换。身份/终局只做非阻塞的短分组呈现，不累计等待时间；不要根节点震动、弹跳或全屏闪光，默认没有持续环境动效。动画不延长既有自动检定220ms或长按推进时序。
7. 保持单一宿主渲染循环，当前Layout树会重建，动画状态不能依赖旧元素长期存在。不每帧分配图片/音频/像素缓冲或因动效额外重建整页。真实命令与视效解耦；重复点击不重复提交，返回/关闭/换页/销毁能取消旧动画，完成回调不覆盖新状态。变换后的绘制、命中、滚动裁剪一致。
8. 后台暂停，恢复不追赶装饰或补播过期短音。减少动态去空间/装饰运动，静态最终状态、即时焦点和相同控件保留，可选透明度≤150ms；复用宿主已有偏好，不默认新增设置，不声称微信已支持系统媒体查询。视频默认不用；FX只在单独授权、可靠处理和实机验收后才考虑，不能贴绿幕矩形充透明。

后续实施验收：逐页实际操作长文/空态/快速开关/重复提交/返回/键盘焦点/滑块边界/减少动态及后台恢复；确认局内HUD、抉择、检定、时序和音画未变。真实Web Canvas和实际微信开发者工具/真机分别记录，不以HTML或Web截图代替微信。由主实施者在全部改动集成后集中运行受影响typecheck/构建等检查一次，不并发检查半成品，不运行不存在的npm test。仅报告实际结果与未验证项，更新既有受影响文档，不另建历史/备份规范。
