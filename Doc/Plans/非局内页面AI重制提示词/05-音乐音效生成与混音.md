# 05-音乐音效生成与混音

## 使用方式

将下方代码块完整复制给能访问本项目的编程／音频 AI，只执行另行委托的本阶段。本轮只覆盖文档，不生成、上传、试听或改音频路由。[整体 UI 主规范](../../UI整体风格方案.md)确定 A，[动效配套规范](../../动效与微交互制作规范.md)约束声画响应；设计批准不代表音乐已生成或听审通过。

你负责第五阶段：制作并接入局外声音。输入为08的MUS/SFX/可选AMB完整A提示词、实际获准MUS-01样片（若尚无，先单独授权制作与听审）、01路由清单。不得假定样片存在，不再发起视觉风格投票。

执行：

4. 检查静音头、截尾、点击噪声、节拍与环境接缝；在实际运行解码器和设备试听，不只看WAV波形。统一相对响度、预留叠加余量，不对极短点击硬套音乐LUFS。循环、时长、声道及各SFX单次事件按08目标逐项处理，未达标不标approved。
5. 在src/audio.ts/src/renderer.ts现有系统中按screen/overlay上下文隔离新增路由，保留音乐/音效/环境三通道和既有音量持久化/静音恢复/0值语义。共享tap、life、ending等文件及局内日志cue不原位替换。菜单弹层通常延续底层曲；game打开管理/声音/详情等目标弹层时保留原局内音乐和地区声，只让目标控件使用新UI提示音。
6. 结局报告可切新局外主题，返回历程必须恢复原游戏上下文曲及地区声；不能全局把life映射MUS-02或ending映射新曲。一次交互只选一个主提示音，不能叠普通点击/选中/确认；拖滑块不连续发声，无效/禁用操作沿用原行为。

受托实施验收：真实操作并试听首页→身份→选卡→局内→管理→设置→结局→返回历程/首页，耳机与扬声器分别记录。验证音量0、重载保存、恢复、后台、快速换页、重复短音、叠加、循环接缝和局内保护。移动端代表性整段会话混音可参考-18 LUFS±2、真峰值≤-1dBTP；不是每个短文件的强制响度。记录实测工具/结果、权利状态与未验证项，无实际生成或试听绝不写“已生成/音质合格”。原位更新既有记录，不另建历史/备份规范。
