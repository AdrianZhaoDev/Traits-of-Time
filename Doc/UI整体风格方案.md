# 《穿越了这次我带大喇叭逆袭》UI 整体风格方案

**状态：A「爆笑开播」已按用户“重做全局”的要求落到 Canvas 客户端，是全项目唯一视觉规范；已执行检查与平台限制见 [README](../README.md#本轮实际验证)。** 客户端仍是 TypeScript + minigame-canvas-engine 1.0.29，以 XML / Flex 构建 Canvas 界面，面向 Web 和微信小游戏，标准逻辑宽 750。独立 HTML 仍仅是风格参考，不是 DOM 游戏或微信验收结果。

批准参考为 [A 首页样板](../local/outgame-ai/02-style/bright-options/a-comic.html)及其 [390×844 / DPR 2 截图](../local/outgame-ai/02-style/bright-options/previews/a-comic-390x844-dpr2.png)、[360×640 / DPR 3 截图](../local/outgame-ai/02-style/bright-options/previews/a-comic-360x640-dpr3.png)。本文件定义统一视觉；[动效与微交互规范](./动效与微交互制作规范.md)定义表现节奏；[文案规范](./文案设计与风格规范.md)定义玩家文字；[技能使用指南](./游戏开发技能使用指南.md)说明制作流程与授权。生产简报和页面提示词引用本文件，不另建一套配色。

## 一、气质、品牌与实施边界

### 1. 视觉主张

明亮的明代市井轻喜剧，像一张有粗墨线和大标题的漫画招贴：浅纸底、番茄红展示字、明黄主按钮，人物和道具轮廓简单，带一点穿越的荒诞反差。光线平直、偏晴日；正文与选择像清楚的现代界面。轻喜剧来自遭遇，不靠满屏吐槽、拟声字或夸张失败惩罚。

- 每屏一个视觉锚点。首页锚点是完整标题与同组喇叭图形；阅读页锚点是当前内容或唯一主行动，不再复制首页英雄区。
- 不用深青／墨蓝氛围、黄昏庭院、金边、厚重档案卷宗、卷轴和帝王盖印作主身份；不转向宫廷、仙侠、赛博霓虹或恐怖。
- 不把漫画风做成幼态圆泡泡、遍地贴纸、每行卡框。高频阅读、重大抉择、死亡与终局尤其克制。

### 2. 品牌与首页固定语义

正式游戏名为 **穿越了这次我带大喇叭逆袭**，完整显示，不截断、不另造简称。首页优先按批准样板分行：

```text
穿越了
这次我带
大喇叭逆袭
```

前两行用 `ink`，末行用 `accent`，允许末行一处明黄套印偏移。可因实际字形和安全宽度重排，但不能裁字、缩成难读的一行或只留下后半句。

- 核心介绍：**带上一件现代物品，去明朝过一生。** 可分两行，语义不改。
- 首页保留四个真实入口：**我要穿越／声音／成就／统计**，不增加登录、商店、续命或领取奖励入口。
- 临时进度提示：**本局进度仅临时保留，关闭或刷新后不能继续。** 必须可见、可读，不被装饰或底部安全区挤掉。
- 红色喇叭仅是品牌识别，不是游戏内物品、固定开局家当、必得奖励或能力；不得暗示人人带喇叭入局。开局仍是随机身份和真实候选家当三选一，只提交一件。

### 3. 设计目标不等于实现授权

| 范围 | 本规范的地位 | 本次允许的变更 |
| --- | --- | --- |
| 首页、开局、成就、统计、声音、管理四页、详情与终局 | A 的统一视觉规范 | 本轮已原位实施 Canvas UI |
| 人生推演主画面、HUD、历史折页、随身物品入口、推进、重大抉择、检定与阶段 | 同样采用 A，不是另一套备选视觉 | 本轮全局任务包含这些 UI；保留玩法、信息与命令契约 |
| 局内既有 FX、音乐、地区环境声及其触发、混音与生命周期 | 保留原有运行契约 | 本轮不重绘、不替换、不改变播放行为 |
| 原局外重制提示词包 | 仍只负责其原有局外范围 | 不把旧提示词或概念图当作本轮客户端验收证据 |

生产 JSON、内容 ID 与引用、概率、检定、阶段图、奖励、成本、事业推进、命令时机和持久化全部保持不变。当前未结束人生仍仅在内存中；已完成人生记录与音量继续按既有本机存储契约保存，不改 `time-travel.*` 键，不以品牌更名迁移或清空记录。不得新增默认选择、槽位、装备、售卖、章节门槛或假数据。

## 二、唯一色彩系统

以下是批准 A 的精确 sRGB 角色值。名称与色值一一对应；实现映射到共享 Canvas token 与宿主 CSS，不能在子页面另造主色，也不能借换肤改动玩法和原有音画。

| token | 色值 | 角色与约束 |
| --- | --- | --- |
| `paper` | `#FFF9E9` | 全屏基础纸色、阅读底；保持明亮和平整 |
| `ink` | `#302826` | 正文、数字、主要轮廓、短硬阴影；不改成纯黑 |
| `muted` | `#67594C` | 次级说明、辅助标签；不是低到看不清的灰字 |
| `accent` | `#BF3527` | 番茄红标题、品牌与明确警告；不是默认主 CTA 底色 |
| `accent-ink` | `#FFF9E9` | 确有必要的番茄红色块上的反白内容 |
| `accent-hover` | `#A42B21` | 番茄红语义操作的悬停／短暂加深；不侵占黄色主行动 |
| `sun` | `#FFDA58` | 主 CTA，配 `ink` 文字、墨线和短硬阴影；少量品牌点睛 |
| `sun-soft` | `#FFF0AC` | 主 CTA 悬停、选中底和少量辅助色块 |
| `surface` | `#FFFDF5` | 次级按钮、弹层与安静内容面 |
| `line` | `#D8C899` | 仅装饰分隔、非交互层次；不能单独充当可操作控件边界 |
| `focus` | `#196C8A` | 仅即时高对比焦点环；不是另一种主主题色 |
| `disabled` | `#E4DDD0` | 禁用底；配可读文字和不可用原因 |

- 一屏主行动优先为 `sun` + `ink`；番茄红承担展示和警告，不能把所有确认按钮染红。
- 普通文字与其实际背景至少 4.5:1；大字和有意义的控件边界至少 3:1。按最终叠图、透明度、状态与字形检查，不把 token 列表当作对比度验收。
- `line` 不足以区分交互边界。按钮、可选项、滑块等用 `ink` 轮廓或其他经验证达到标准的有意义边界；普通列表只用留白和装饰分隔。
- 不只靠颜色表达涨跌、稀有度、选中、禁用、错误和风险：保留数值、正负号、标签、勾记或明确原因。不得用红绿把未知结果包装成好／坏答案。
- 可从 `ink` 派生低透明度遮罩；遮罩强度以不透出干扰阅读的信息为准，不能演变为深色整屏主题。正文面仍须稳定、不透纹理。

## 三、字阶、缩放、布局与无障碍

### 1. 字体与文字绘制

- 展示字体 `font-display`：`"Microsoft YaHei", "PingFang SC", sans-serif`，正体、粗重；标题建议 800–900 字重，以平台可用字形为准。
- 正文／按钮字体 `font-body`：`"PingFang SC", "Microsoft YaHei", system-ui, sans-serif`。正文用正常或中等字重，动作和关键信息适度加粗。
- 不以宋体、毛笔书法、斜体标题或伪古籍字作为主身份。不假定已打包新字体；引入字体前另核许可、中文覆盖和包体。
- 标题、按钮、正文、数值、风险与状态均由程序绘制，不能烘进插画、背景或视频。完整文本继续进入既有 Web 无障碍语义层；该层不是第二套视觉界面。

以下尺寸是**最终可见 CSS px 目标**，不是当前运行测量，也不能原样当作 750 逻辑单位：

| 层级 | 目标与使用范围 |
| --- | --- |
| 首页展示标题 | 按批准样板形成大／小／大节奏，首行约 41–58、过渡行约 28–36、末行约 46–60；实际宽度不足先重排，完整名称优先 |
| 普通页面标题 | 22–28，明显小于首页；不为每个弹层再做巨型字标 |
| 区块标题／重要数据 | 18–22；数字与标签对齐，不把每个数值做成广告字 |
| 正文／选项／主要按钮文字 | 正文目标约 16 或以上，正文行高约 1.5–1.65；选项与动作不能靠缩字塞下 |
| 重要提示／风险／进度警告 | 目标 13–14 或以上，关键条件可升至正文级；不能因放在页尾就降为装饰 |
| 非关键信息的短标注 | 不低于 12；不能用此下限呈现长正文、关键成本或不可逆后果 |

### 2. 750 逻辑单位、CSS 尺寸与 DPR

以最终显示的 Canvas 宽 `W`（Web 为实际 CSS 宽；微信为宿主窗口的等效可见宽）等比映射逻辑宽 750：

```text
可见 CSS px = 逻辑单位 × W / 750
目标逻辑尺寸 = 目标 CSS px × 750 / W
最小命中逻辑尺寸 = ceil(44 × 750 / W)
主画布位图宽约为 W × DPR
```

DPR 只影响位图采样密度，不把按钮或字号变大。截图物理像素、设计逻辑单位和可见 CSS px 必须分别记录。带边栏、嵌套缩放或非全宽 Canvas 时，以实际 Canvas 映射为准，不拿手机标称宽代算。

- `W=360` 时，44 CSS px 命中下限为 **92 逻辑单位**；`W=390` 时为 **85**。32 逻辑单位在 360 宽仅约 15.36 CSS px，不能一概宣称达到正文 16 px。
- 正文最低目标按实际宽度换算并实测换行。例如 360 宽达到 16 CSS px 至少需约 34 逻辑单位；390 宽至少约 31。字体回退、内边距、行高和容器缩放仍需一起检查。
- 相邻操作目标至少留约 8 CSS px；换算同样基于 `W`。视觉图标可小，透明命中区仍须满足最小尺寸且不压到邻居。
- 不把固定内容宽或“每行能放几个字”写成通用保证。使用真实字体测量、现有 XML / Flex 和明确的滚动区域，允许长中文名称和多行选项增高。

### 3. 页面节奏与安全区

页面水平留白通常以约 20–24 CSS px 为起点，区块间距按 8／16／24／32 CSS px 的节奏组织；这是目标间距，不要求把窄屏可用宽强行扣到相同数值。安全区由平台与宿主实际布局共同确定：现有微信适配读取宿主安全区，Web 适配返回零 inset；不能据此声称浏览器已解决刘海或底部遮挡。

短屏按以下顺序处理：缩短装饰插图和英雄区空白 → 减少非必要区块间距 → 允许内容纵向滚动。不得缩小关键正文、裁掉标题、警告或按钮，也不以横向溢出补救。固定操作区与滚动正文互不遮盖，焦点进入屏外控件时要能看见目标。

管理四页签按真实文字宽度分配空间，标签保持单行，不因等宽分栏压小「现代词条／生涯成就」；必要时整组分两行，而不是裁字或依赖横向溢出。退出事业等风险操作与普通返回分组，不把所有底部按钮都做成同级黄色主行动；这些布局规则不改变页签选择或返回语义。

Web 保留既有同步语义、键盘操作和模态焦点约束；焦点即时显示，使用 `focus` 轮廓，与选中勾记区分。触屏没有 hover 依赖。微信不能因没有 DOM 语义控件而丢失可读标签、状态说明和足够命中区；本规范不声称当前已具备平台读屏能力。

## 四、墨线、阴影、材质与素材

### 1. 局部重、大片轻

| 元素 | A 目标规则 |
| --- | --- |
| 主 CTA | `sun` 底、`ink` 字、约 2 CSS px 墨线，圆角约 10 CSS px；短硬墨色偏移阴影以横 4／纵 5 CSS px 为参考，无模糊光晕 |
| 主 CTA 按下 | 下／右移动 1–2 CSS px，同时减少阴影；命中区和逻辑位置不跟着跳 |
| 次级按钮 | `surface` 底、`ink` 字和约 1.5–2 CSS px 轮廓；小圆角，无主 CTA 同级厚阴影 |
| 选项／交互卡 | 安静底面；选中用 `sun-soft`、更强 `ink` 边线及勾记／「已选」；未选中不做厚实悬浮卡堆 |
| 正文／普通列表 | `paper` 或 `surface`、留白和 `line` 分隔；不为每行附黑框、软阴影或纸张翘角 |
| 弹层 | 单张稳定浅纸面，必要的墨线／短硬影用于与底层分离；内部内容不层层套框 |
| 首页英雄图形 | 简单轮廓、局部粗墨线和明黄色块，允许一处 2–3 CSS px 套印偏移；不复制到正文和小字 |

材质以平涂和极淡纸感为主。纸纹不得穿过正文、数值、选项或滑块影响对比；不做做旧脏斑、金属浮雕、金光描边、磨砂玻璃或摄影级景深。阅读页装饰只留小标题符号或极少边角图形；结局进一步减量，不再重复喇叭、爆炸线或庆祝贴纸。

### 2. 插画与图标

明代生活场景使用简明剪影、易辨服装与物件、平直晴日光。重要主体不与标题和按钮争抢焦点；插画里的招牌与字样不能替代实际界面信息。操作图标使用统一线宽、尺度和留白，箭头、返回、声音等与文字配合，不以 emoji 充当主视觉或含义不清的图标。

背景如需填满容器，等比 cover：`s=max(容器宽/图宽, 容器高/图高)`，再按构图裁切；不能拉伸。母图必须说明主体与可裁区域；最终安全区由各屏比例、程序文字和按钮决定，不能用一个百分比承诺所有设备都不裁。详情物品图优先 contain，保持轮廓完整。

### 3. 资产、权利与失败处理

- 用户来图是 140×106 RGB 缩略图；现有头像是从中原生裁出的 **38×38** 小图，不是高清母版。小图不能放大冒充首页主视觉、商店图标或微信发布图。
- A 样板中的简化矢量喇叭是构图概念，不是新获批准的高清品牌 logo；正式发布资产仍需足够清晰的来源、单独审核与权利核查。
- 资产审批应记录用途、原生尺寸、透明通道、显示尺度、锚点／裁切、来源／许可、输入与输出哈希和批准状态；沿用现有清单，不把未经生成的计划标为成品。
- 原有物品图、像素图集、MP3 及 [媒体来源说明](../licenses/media-sources.txt)保留，不把未知权利材料补写为 CC0／MIT，也不篡改截图、测量或哈希证据。
- 本次文档批准不授权外部生图、视频、音乐、上传参考或批量生产。必须先明确供应商和预算／额度；密钥可用、CLI 已登录或技能已安装不代表同意调用。
- 默认采用静态画面，不要求视频、持续尘埃或光束。图片失败用 `paper`／`surface` 和程序文字保证可操作，保留真实错误提示；不以另一张虚构素材或合成声音冒充成功。

| 管理·现代词条 | 相同页头、浅纸清单，名称与说明优先 | 仅按现有来源显示真实持有的现代词条与空态，不增加效果或替换名称来源 |
| 管理·家当 | 与现代词条同一阅读节奏，少量真实图形即可 | 真实本土家当、稀有度、说明和空态；不新增装备、出售或领取操作 |
| 管理·生涯成就 | 与其他管理页同字阶和间距，名称／元信息／短评分层 | 沿用当前本机记录、本局与终局成就的实际合并来源，不误称全部仅来自本局，不编造空态条目 |
| 物品详情 | 安全区内的浅纸浮层；标题、稀有度、完整说明与关闭优先 | 真实检定修正及其上限等既有说明；保持现有关闭方式与层栈，不新增自动消失时限；不修改下层人生画面 |
| 终局报告 | 安静纸面、朴素粗体标题、真实生平与汇总；仅少量番茄红语义强调，不盖大印、不喇叭庆祝 | 年代、年龄、历经年数、真实终局原因、家资、五属性、最高身份、事业、主／其他成就及家当完整；保留返回历程、重启和返回首页 |
| 启动加载／失败（宿主兜底） | 保留清楚的宿主文字与可靠原生表面，不要求背景、插画、动效或音乐 | Web 启动状态／noscript、微信加载与失败提示按现有路径工作；不新增重试、清档、登录或伪进度，不为风格统一牺牲素材不可用时的可操作性 |

从重大抉择打开管理页，返回后必须仍是原待选抉择。退出事业确认、开局家当确认等操作按原状态执行，不能借全新视觉新增确认步骤或跳过必要提交。

## 七、交互状态、层级与反馈

### 1. 状态覆盖

| 状态 | 视觉与行为标准 |
| --- | --- |
| 默认 | 一个清楚的主行动；可交互边界与普通分隔不同，完整动作文字可读 |
| 悬停 | 仅精确指针平台启用，主按钮／次级按钮可用 `sun-soft`；触屏无需悬停才能看到信息 |
| 按下 | 立即给颜色／硬影压下反馈；主按钮移动 1–2 CSS px，不能移动命中区域、遮字或改变选中状态 |
| 选中 | `sun-soft` 底、更强 `ink` 线、勾记／「已选」；页签与选卡均不只靠色差 |
| 焦点 | `focus` 高对比轮廓即时出现，与选中标记独立；不淡入、不脉冲，不被弹层边缘裁切 |
| 禁用 | `disabled` 底、可读 `muted` 或 `ink` 字、明确不可用原因；不以全组低透明度隐藏关键条件，不响应成功反馈 |
| 加载／忙碌 | 使用真实忙碌状态和明确文案，保留布局、防重复；只在实际不可操作时禁用，不为播放入场而锁输入，不伪造进度 |
| 空态 | 说明当前确实没有什么，以及既有可用操作；不放演示记录、奖励占位或假物品 |
| 警告／失败 | `accent` 与明确文字共同说明问题；错误就近呈现且不压住选项、关闭或返回，素材失败仍保留可行操作 |
| 完成／成功 | 只在真实结果提交后改变状态；名称、数值、记录均来自真实来源，默认不额外加礼花或「已保存」承诺 |

滑块轨道／滑块头有可辨边界、数值和静音／恢复状态；拖动时直接跟手，不让显示音量落后实际值。风险与错误不能只靠声音。长正文可完整换行和滚动，不用省略号遮住条件或结果。

### 2. 合成与输入层级

沿用现有基本界面与顶层弹层两棵 Layout 树及宿主合成顺序，不要求新建界面框架：

1. 背景／静态装饰：无输入，不承载正文或关键状态。
2. 基本 Canvas UI：当前首页、身份或人生画面及其布局。
3. 既有局内像素 FX：在基本 UI 之上、交互弹层之下，不接收输入；本次不动其实现。
4. 弹层遮罩与最顶层面板：只有当前顶层接受输入，下层不能穿透；可关闭与必选面板按原控制契约区分。
5. 当前层焦点和必要通知：不盖住动作、风险和数值；语义顺序与视觉可操作层一致。

重大抉择、开局选卡、检定不能靠点遮罩、返回键、退出动画或其他弹层绕过。普通可关闭弹层保留原返回路径；关闭后不丢失被遮盖的待选流程。装饰绘制中的 alpha、transform、clip 和采样状态须限定作用域，不能泄漏到下一层。

## 八、动效与声音目标

A 的 UI 表现是利落的纸面／硬按钮反馈：按压 80–120ms，颜色反馈约 160ms，进入 160–220ms、退出 100–160ms，选中 120–160ms；空间位移不超过 6 CSS px。以上是后续实现的**目标标准，不是现行性能或播放测量**。详细中断、生命周期和减少动态要求见[动效规范](./动效与微交互制作规范.md)。

仅可缩短、打断或跳过表现过渡，不能跳过身份确认、家当提交、重大抉择、检定或任何真实命令；不新增跳过按钮。真实结果可用时立即可读、可按原条件操作，不为开局安排强制长转轴或翻牌。无根容器震动、弹跳、全屏闪白和例行尘埃／光束；减少动态取消空间运动和装饰动画，保留同样信息、控件和即时焦点，可仅用不超过 150ms 的淡变。

音乐的风格目标是明亮、温暖、略俏皮的木质／拨弦短动机，为阅读留空间；不加人声、喇叭噪声、小丑喜剧音或厚重史诗／阴森配乐。终局收敛，死亡不当笑点。该目标不替换现有音乐和地区声，不新增音频架构或试听结论；新音频制作与上传仍需单独授权。
