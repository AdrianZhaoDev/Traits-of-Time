# 动效与微交互制作规范

**状态：A「爆笑开播」的表现层规范，配套全局 Canvas UI 实施。** 唯一视觉依据为 [UI 整体风格方案](./UI整体风格方案.md)，实际验证与限制见 [README](../README.md#本轮实际验证)。本轮获授权改变全局 UI 外观与局部按压表现，保留推进、抉择、检定及现有 FX／音频的运行契约，不以换肤扩大音画变更范围。

现行客户端是 TypeScript + minigame-canvas-engine 1.0.29，使用 XML / Flex 与 Canvas，面向 Web 和微信小游戏，逻辑宽 750。动效应复用现有宿主合成与输入体系，不引入另一套引擎节点、动画框架或第二个帧循环。独立 HTML 风格样板不是游戏运行层。

## 一、动效的职责与禁区

A 的动效像纸面上的按钮被利落按下：短、清楚、能立刻打断。它解释状态和层级，不负责替玩家做决定，也不把轻喜剧变成喧闹综艺。

- 高频推进、切换页签、列表阅读和键盘操作以即时响应为先；没有信息收益的动画直接省掉。
- 先显示真实状态，再决定是否需要短过渡。不能让动画完成回调负责抽取身份、决定家当、提交选项、执行检定、记录成就或持久化。
- 完整正文、真实数值、成本、风险、错误与当前可用控件在首个可显示帧就可读、可操作；不逐字揭晓、不隐藏后果等待演出。
- 只允许结束、缩短或跳过**表现过渡**，不能跳过身份确认、家当提交、重大抉择、阶段检定或任何原有命令；不新增跳过按钮。
- 无根容器震动、夸张弹簧、卡牌砸入、从零放大、整屏闪白、印章重砸、持续抖动或长转轴。死亡与灾难不安排搞笑反应，终局不以喇叭或礼花抢走内容。
- 默认静态首页。不要求持续尘埃、光束、视频或长时间待机表演；不能把尚未制作的效果写成现成素材。

## 二、单位、时长与曲线

本节全部数值是**制作标准和预算，不是当前播放测量、设备性能或已实现声明**。既有命令层等待、按住推进节奏、自动检定时机和 FX 图集帧率不按本表改动。

### 1. 可见尺寸换算

以实际 Canvas 可见宽 `W` 等比映射 750 逻辑单位：

```text
可见 CSS px = 逻辑单位 × W / 750
目标逻辑位移 = 目标 CSS px × 750 / W
```

DPR 决定位图采样，不改变可见位移、字体或命中区。任何缩放、留边和嵌套容器均须按真实映射计算，不把“6 逻辑单位”误写为“6 CSS px”。命中区遵守主规范的至少 44 CSS px、相邻约 8 CSS px 规则，表现移动不改变布局和命中区域。

### 2. 统一时长表

| 表现 | 目标时长 | 空间／视觉幅度 | 输入与信息规则 |
| --- | --- | --- | --- |
| 按压硬按钮 | 80–120ms | 主 CTA 向下／右 1–2 CSS px，短硬影同步收短；次级动作以底色反馈为主 | active 状态即时生效，松开／取消即时解除，不等待播放后才提交 |
| 悬停／轻颜色反馈 | 约 160ms | 使用 A 的 `sun-soft` 等既定状态色，无循环呼吸 | 仅精确指针悬停；触屏和键盘不依赖此过渡 |
| 页面／弹层进入 | 160–220ms | 可选小位移，最大 6 CSS px，或底面轻淡入；无缩放弹跳 | 真实文字和控件不延迟显现；不锁输入，不给每行加排队入场 |
| 页面／弹层退出 | 100–160ms | 从当前表现值退去，不大范围飞出 | 层栈按真实操作更新；残留画面不收输入，也不能让输入落到错误底层 |
| 选中切换 | 120–160ms | 浅黄底／墨线短变，勾记或「已选」立即出现 | 选中 ID 与语义状态即时同步；切换不能触发提交或重新抽取 |
| 数据／结果变更 | 即时 | 显示最终真实值；需要提示时只短变边线或附原有变化文字 | 不使用假滚字、虚假中间值、延迟数字来冒充结算 |
| 键盘焦点／高频导航 | 即时 | `focus` 轮廓，无移动、缩放、淡入或脉冲 | 聚焦即可识别；滚动显露目标不等待装饰过渡 |
| 减少动态 | 即时，或不超过 150ms 的可选淡变 | 去掉空间和装饰运动，保留清楚的静态状态 | 控件、信息、命令时机与普通模式相同 |

按钮位移是压短硬影的局部反馈，不将整个页面或正文一起挪动。位移上限不是每处都必须移动的配额；列表、数值与终局优先不动。

### 3. 曲线

A 样板的短响应曲线为 `cubic-bezier(0.2, 0.7, 0.3, 1)`，用于新的短进入、退出和状态过渡。Canvas 实现应求取相同的时间曲线，不能把贝塞尔参数直接当位移值；沿用现有工程能力，不为它加入动画依赖。连续拖动、滚动和音量反馈直接跟手，不做追赶补间；真正匀速的表现才使用线性时间。

不为每个页面各手调一条近似曲线，不使用慢启动、超冲、反弹和戏剧性停顿。退出通常短于进入；频繁操作或中断时可以直接落到最终表现值，而不是坚持播完整段。

## 三、Canvas 宿主契约

### 1. 一个表现时钟

现有 `src/renderer.ts` 负责宿主帧循环与合成，`src/view.ts` / `src/ui.ts` 构建 Layout 树，`src/platform.ts` 提供视口和前后台事件，`src/effects.ts` 在宿主调用时绘制原图集。后续新增的 UI 表现必须接入这一体系，不建立平行控制器或重新实现布局、滚动和输入。

- 宿主每帧提供同一个 `now`；新表现动画只读取该时间与当前界面状态，不各自调用独立时钟推进。
- 进度可按 `clamp((now - start) / duration, 0, 1)` 求得，再映射到已确定的表现起点／终点。起点来自当前显示值，不从预设初始帧强制重启。
- 不新增 `requestAnimationFrame`、常驻 interval 或用于逐帧更新的 timeout。现有引擎 ticker 的启停和滚动仍由原宿主管理，不另开一套调度。
- 大幅时间跳变、后台返回或布局重建时，新表现允许立即完成或从当前状态重新基准化；不累计隐藏期间的帧数，不补放过时动效。
- 这是一项新增表现的接入约束，不声称现有所有计时点已经使用同一个时间源；不能借统一时钟改动游戏推进、按住阈值或自动检定延时。

### 2. 表现不碰游戏随机源

短过渡是当前状态与时间的确定性函数，默认不需要随机数。不得读取、推进或重新播种游戏 PRNG；不得在逐帧绘制、入场、重绘、减少动态切换或资源加载回调中抽取身份、候选或结果。装饰也不能借用游戏随机源；本规范不新增需要随机粒子的效果。

同一份已提交游戏结果，在普通模式、减少动态、不同帧率、打断过渡或资源失败时，候选、概率、日志、属性和存储必须一致。动画不生成命令，不补发漏播“奖励”，不把视觉计数当真实数据。

### 3. 合成、布局与资源

沿用基本 UI → 既有局内像素 FX → 顶层遮罩／弹层 → 当前层焦点与必要通知的合成关系。装饰和 FX 不接收输入；顶层弹层约束下层输入，关闭与必选门禁以原控制层为准。

- 尽量只改变局部绘制变换、透明度和必要状态色，不逐帧重算 XML／Flex、文本换行、容器宽高或整棵布局。
- 缓存可复用的图像与静态内容。不得每帧创建图片、Canvas、像素缓冲、闭包或无用对象，不为简单压下反馈增加模糊、滤镜或整屏离屏渲染。
- 每次局部变换、透明度和裁切均限定绘制作用域，绘完恢复，避免后续正文、焦点、遮罩或 FX 意外继承。
- 新 A 插画按真实素材类型选择采样；原像素图集继续保持原裁切、帧率、锚点与最近邻采样，不拿新 UI 风格当重导出理由。
- 素材失败保留清楚的程序文字和可用操作，按既有错误路径报告；不临时生成另一种效果或合成音效冒充加载成功。

## 四、中断、输入与生命周期

### 1. 中断优先于完整演出

快速打开再关闭、切页签、改选家当或反向操作时，从当前表现值重定向，或直接显示最新静态状态。不从零开始叠加第二段，不让旧动画结束回调把新界面盖回去。

- 逻辑选择、层栈和忙碌状态先按原控制契约更新；表现只读取它们。旧页面关闭后，旧任务不得再写其布局、焦点或通知。
- 离场残影没有动作句柄。输入始终路由到当下实际顶层，不能穿透到尚被遮盖的推进按钮或上一页。
- UI 因字体、尺寸、安全区或内容变化重建后，旧引用失效；先停止相关表现并确认当前对象，不能继续写回被复用的元素。
- 动画取消不撤销已提交命令、不重试命令、不清空选择；命令失败按真实失败显示，不以回弹、复位或吞异常包装为成功。
- 对必要的家当选择、重大抉择和检定，打断表现仍停在同一个待处理状态。返回键和遮罩不能通过退出动画绕过必选流程。

### 2. 点击、按住与滚动

普通按钮保留原点击／松开提交规则，推进仍按原按下与长按快进契约执行；两者不能因为采用同一外观就互换时机。装饰不模拟额外点击，按住不排队补发推进。

持续推进遇到原有待选卡牌、重大抉择、未完成阶段／检定、终局、忙碌、遮罩层或原取消条件时，继续由既有逻辑约束。切后台、失焦、触摸取消、拖出和尺寸变化不得遗留按压态；恢复后不自动续按。不得用本规范的 80–120ms 动画替换运行中的长按门槛或重复间隔。

滚动沿用原行为，不强制为每条新经历加飞入和翻页。查看最新、原有自动定位、用户拖动与键盘滚动各自保持原契约；不在用户阅读旧内容时另加与手势争抢的装饰滚动。

### 3. 生命周期矩阵

| 时机 | 新增表现必须做什么 | 不得做什么 |
| --- | --- | --- |
| 页面离开／弹层关闭 | 停止并清除所属短过渡、按压外观与失效引用 | 旧回调继续改新页面、补发游戏命令或重开音频 |
| 非顶层／被遮挡 | 不让背景装饰争抢注意，输入只给真实顶层 | 在保护区添加新待机循环，或为“暂停动画”改变游戏数据 |
| 宿主进入后台／失焦 | 停止装饰计时，沿用原手势取消与音频生命周期 | 累计后台时间后快放、继续按住或触发旧提示音 |
| 返回前台 | 按最新真实状态恢复静态界面，重置新表现的时间基准 | 回放错过的揭晓、死亡、成就或任何已完成反馈 |
| 视口／DPR／安全区变化 | 重算实际映射与布局，结束不再适用的位移，保持焦点可见 | 用旧坐标继续漂移，修改命中区域来追随装饰 |
| 减少动态偏好变化 | 立刻转为相同信息的静态状态，结束空间运动 | 重新抽取结果、清空选择或要求重新开始人生 |
| 整体销毁 | 释放新增订阅、资源回调与表现引用，复用原宿主释放流程 | 额外常驻循环、销毁后绘制或访问已释放资源 |

## 五、各界面的 A 表现标准

下列标准覆盖全局 UI；本轮实现保持静态阅读优先，不为进入动画延迟真实信息或命令。具体已观察项目和未完成的平台测量以 README 为准。

| 场景 | 允许的短表现 | 保留与禁止 |
| --- | --- | --- |
| 首页 | 黄色主按钮硬影压下；普通面板短进入／退出 | 完整标题与四入口首屏可读／可达；无例行浮尘、喇叭摇晃、噪声或视频要求 |
| 身份揭晓 | 浅纸面整体短进入，信息直接出现 | 年份、年龄、身份、地区与阶层来自已生成状态；不先播虚假候选，不强制 1.5–2.4 秒转轴或翻牌 |
| 家当三选一 | 浅黄选中底和墨线短变；「已选」即时出现 | 三个真实候选立即可读、可按原规则选择；无默认选中，确认仍只提交一件，动画不决定候选或提交时机 |
| 成就／统计／管理页签 | 即时切换为先，必要时仅底面轻淡变 | 保留真实记录、空态、进度、退出代价与状态；没有数字滚动、假解锁和每行入场 |
| 声音设置 | 拖动直接跟手，标签／百分比即时同步 | 不补间实际音量、不为每次拖动新增试听，不改变静音恢复和本机保存 |
| 物品详情 | 小幅或仅淡变，与来源建立层级关系 | 完整说明和收起操作不延迟；不新增自动消失计时，底下博古架与 FX 不改 |
| 人生主画面／HUD | 真实数值即时显示为墨字，变化保留原说明 | 不滚假数、不抖动正文，不改变数值生效时机 |
| 历史折页 | 保留原滚动和最新定位，静态阅读优先 | 不逐字播放、不强制自动翻页、不删行动／结果／成本等正文 |
| 推进／重大抉择 | 可用与不可用状态即时呈现，按压反馈短而局部 | 不跨过门禁、不新增等待，不用色彩或演出替玩家选最优答案 |
| 阶段／检定 | 任务、属性、成功率与真实结果稳定可读 | 原自动处理和继续检定按命令层执行；不假转盘、不暗示动画速度改变概率，不因关闭过渡漏执行任何阶段 |
| 终局报告 | 内容直接呈现，可选浅纸面短淡入 | 死因与汇总优先，保留返回历程／重启／首页；无盖印冲击、失败笑梗或新增庆祝 FX |

## 六、减少动态与可访问性

Web 使用可用的 `prefers-reduced-motion` 系统偏好；微信以实际宿主能提供的系统／应用偏好为准，未验证前不声称存在自动映射。本规范不顺手新增偏好开关或设置页。

减少动态时取消新 UI 的位移、缩放、套印移动、连续装饰和排队入场，可直接切换，或仅保留不超过 150ms 的短淡变。保留静态的主次层级、选中标记、错误和加载文字，不是把所有反馈清空。焦点环始终即时出现；键盘动作不播放空间过渡。

默认模式与减少动态模式具有相同的文字、控制、命中区、命令门禁和最终结果。静音时也能识别操作、风险和错误；不以声音作为唯一反馈。任何新动效不能让闪烁、变化底色或透明叠图降低正文可读性。

## 七、既有 FX 与音频的保护

当前原始像素图集由 `src/effects.ts` 在宿主合成时播放：烛火、家资增长、死亡与成就；素材来源与许可见 [媒体来源说明](../licenses/media-sources.txt)。当前实际触发由渲染订阅的真实日志决定，不能把旧文档中未核实的排除规则当作已经实现的行为。

本文不调整这些图集的内容、帧数、帧率、位置、触发条件、减少动态或前后台行为，不将其替换为程序绘制或新生图，也不新增整屏闪光。新 A 界面的终局克制要求不等于本次获准改写现行死亡／成就播放路径。

音频继续由 `src/audio.ts` 使用音乐、音效、环境声三个通道及既有本机设置。保留真实手势解锁、静音、循环／提示音复用、后台停止、前台只恢复当前循环和资源失败静音的契约；不因动画完成、hover、重绘或页面恢复补播声音，不改音量曲线和存储键。

A 的新音乐目标是明亮、温暖、略俏皮的木质／拨弦短动机，留出阅读空间；不使用人声、喇叭噪声、小丑喜剧音或厚重史诗／阴森配乐。当前音乐与地区声不替换。新音频需要明确供应商和预算／额度授权，登录 CLI 或配置密钥不等于同意请求／上传；本文件没有生成、试听或混音测量结论。

## 八、后续实施验收规则

以下仅供获授权的实现任务验收；文档规范和独立HTML参考不构成运行验收，只有实际执行并记录的项目才能记为完成。

1. 在实际 Canvas 与目标微信设备记录普通／减少动态的真实表现、可见宽高和 DPR；独立 HTML 截图不是 Canvas 或微信证据。核对位移、触控区域与字阶使用的是可见 CSS 尺寸，而非位图像素。
2. 覆盖快速开关、反向切换、重复选中、长按取消、拖动取消、后台／前台、失焦、尺寸变化和销毁；没有旧回调、残留按压或错误层输入。
3. 核对身份、候选、选项、检定、日志、属性、已完成记录和音量不受动画、中断、帧率或减少动态影响；不能通过跳过过渡绕过真实决策或阶段。
4. 确认新增表现共用宿主时间与循环，不改 PRNG，不逐帧分配资源或重建布局，不更改既有 FX／音频和运行门禁。
