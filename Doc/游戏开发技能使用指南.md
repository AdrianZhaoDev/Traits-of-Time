# 游戏开发技能使用指南

本项目按需安装了两组 AI 开发技能，目录为 `.agents/skills/`。技能帮助助手选择流程和使用脚本，不会自动修改游戏，也不是游戏运行时插件。实际客户端是 **TypeScript + minigame-canvas-engine 1.0.29**，使用 XML / Flex 与 Canvas，面向 Web 和微信小游戏，标准逻辑宽 750；Web 的同步无障碍控件不是第二套视觉界面。

全项目采用已批准的 **A「爆笑开播」**，唯一视觉依据是 [UI 整体风格方案](./UI整体风格方案.md)，表现节奏见 [动效与微交互规范](./动效与微交互制作规范.md)，玩家文字见 [文案规范](./文案设计与风格规范.md)。技能中的通用推荐不得覆盖批准的黄色／墨色主行动、番茄红展示字和粗重正体无衬线，也不能扩张任务范围。

风格批准是文档与制作目标，不是运行换肤、外部请求或批量生产授权。本次不运行技能脚本、安装依赖、生成／上传媒体或改代码。当前局内画面、HUD、历史、博古架、推进、抉择、检定及既有 FX／音画仍受保护；局外任务包括从局内打开的相应弹层，但不修改其下面的保护区。

## 怎么使用

直接告诉助手要做什么，并说明使用哪个技能。例如：

- “用 `generate2dsprite` 为手摇手电制作透明图标，先给出尺寸和风格方案，不要调用付费服务。”
- “用 `create-game-assets` 检查这批卡牌图片的尺寸和透明通道。”
- “用 `game-ui-ux` 检查竖屏开局界面的文字和安全区域。”
- “用 `save-systems` 检查已完成人生记录与音量的本机保存风险，不要增加未结束人生的跨次续局或替换存储格式。”

支持显式调用的客户端也可以使用对应命令，如 omp 的 `/skill:generate2dsprite` 或 Codex 的 `$generate2dsprite`。是否可用以当前客户端技能列表为准；若新安装后未识别，重新打开会话或直接读取 `.agents/skills/技能名/SKILL.md`，不沿用其他会话的安装／登录状态作为证据。

## 什么时候使用

### 素材制作：Agent Sprite Forge

| 技能 | 适用场景 |
| --- | --- |
| `generate2dsprite` | 卡牌、家当、物件图标的制作，以及已有图片的抠图、切帧和图集处理。 |
| `generate2dmap` | 标题、结局或事件背景，以及确实需要时的分层场景。 |
| `video2dsprite` | 将已批准角色／生物母版制作成动作，或处理用户提供的视频；不是 FX／物件图集工具，A 默认不需要视频。 |
| `codeart2d` | 仅用户明确要求代码绘图，或媒体路由实际返回 `no-route`（退出 3）时使用；必须标明代码绘制，不冒充 AI 生图。 |
| `generate2dmedia` | 图像／视频服务路由、能力、密钥与费用记录；任何真实请求均先满足下文的独立授权要求。 |

这五个技能之间有相对路径依赖，应一起保留。项目已有 `pixelfx` 技能和像素特效导出流程：制作烛火、奖励等效果前，先检查已有素材。Forge 的 `fx_pixelfx.py` 若要调用 pixelfx，仍需单独取得 pixelfx 源码并指定其路径；已有同名技能不等于已经安装源码。

### 游戏开发：通用技能

| 技能 | 适用场景 |
| --- | --- |
| `create-game-assets` | 统一素材风格，检查图片尺寸、透明度和来源。 |
| `game-ui-ux` | 检查竖屏布局、文字、安全区域和不同屏幕比例。 |
| `game-feel` | 在已批准范围内规划短反馈；按 A 规范克制处理，不自动加入抽卡砸入、震屏、闪白或终局盖印。 |
| `dialogue-systems` | 梳理事件分支、选项条件和叙事流程。 |
| `save-systems` | 检查已完成人生记录、音量、版本兼容与数据完整性；当前未结束人生仅在内存中，不能把技能建议当续局功能授权。 |
| `performance-optimization` | 在实测卡顿后定位脚本、图集、内存或渲染瓶颈。 |
| `audio-design` | 设计背景音乐、音效分类和音量控制。 |
| `improve-animations`（若当前客户端提供） | 只读梳理现有动效与中断／减少动态问题，为 A 表现标准提供依据，不直接改源代码；不假定它随上述两组本地技能安装。 |

这些技能的部分示例针对其他引擎；只采用与本项目兼容的流程原则，不复制其节点、补间、材质或导入 API。沿用当前 `src/renderer.ts` 的宿主合成与输入、`src/view.ts` / `src/ui.ts` 的 XML / Flex 构建、`src/platform.ts` 的平台接口，不新建 DOM 游戏或第二个动画循环。事件、卡牌和存储继续使用原契约，不因安装技能改变内容格式、ID、概率或存储键。

## 按现有工程交付

1. 先读 UI 主规范、对应页面与相关源文件，确定是文档、局外实现还是明确获准的局内实现；A 是唯一目标，不重新发散配色或生成备选方向。
2. 检查现有 `public/art/`、`public/fx/`、`public/audio/`、资产清单与 `licenses/`，先复用适用且权利明确的素材。38×38 品牌头像不是高清母版；样板矢量喇叭不是另获批准的商店 logo，更不是开局物品。
3. 制作前在已有清单中写清用途、实际显示尺度、原生尺寸、透明度、裁切／锚点、采样、来源和批准状态。750 逻辑单位、Canvas 可见 CSS 尺寸与 DPR 位图密度分别处理，不根据逻辑宽猜字号、命中区或素材分辨率。
4. 未获得供应商与预算／额度授权时，只做不发请求的计划、dry-run 或任务允许的本地处理；不通过已登录 CLI 试跑“验证能力”，不擅自批量生产。仅当用户要求实际制作时才进入相应素材流程，A 默认使用静态图，不例行制作视频、尘埃或光束。
5. 接受真实输出后，再按原生尺寸、alpha、边缘、显示大小和许可审查；保留真实提示词、输入／输出哈希、实际路由、返回模型与费用状态。计划不是成品，QA 数字不是视觉批准，WARN／FAIL 不得隐去。
6. 本项目运行资源从 `public/art/`、`public/audio/`、`public/fx/` 提供，经 `platform.asset(...)` 定位；微信构建复制到 `media/` 分包。只有明确获准导入后才更新运行资源和相应实际清单。文本／按钮仍由程序绘制；不能把整张界面烘成图，也不能把通用导出包或其独立 JS 播放器直接塞进运行时。
7. 后续实施按当前 `package.json` 与任务范围安排验收：`prepare:assets` 核查必需文件并同步许可，`typecheck`、Web 构建与微信构建各有职责。构建成功不等于图片、动效、音频或微信真机通过；报告只写实际执行和观察到的结果。本次文档覆盖不执行这些命令。

生产 JSON 位于 `assets/resources/data/ming_end/`，不是素材技能的输出目录。不得用新媒体流程改 ID、规则、候选、奖励或概率；`public/` 是受版本管理的必需素材源，不是可清理缓存。也不得依赖旧 `dist-*` 或已删除工程作为缺失素材的兜底。

## 本地脚本和依赖

图片处理需要 Python 3.10+、NumPy 和 Pillow；SciPy 用于部分处理的加速。`create-game-assets` 的图片检查脚本需要 Pillow `>=10,<14`。部分 JavaScript 工具需要 Node.js；本项目现有要求为 Node.js 22.22.1+。视频处理另外需要 PATH 中有 FFmpeg **和** ffprobe 5.1+；SVG 渲染还需要上游列出的受支持渲染器。这些额外工具不是游戏运行时依赖。

本次安装的是技能目录，不包含上游仓库根目录的维护工具；若上游提示执行 `tools/install_skills.py` 或 `tools/vendor_sync.py`，需要另外取得对应版本的上游源码，不能直接从本项目根目录运行。

WSL/Linux 优先复用项目本地 Python 环境 `local/agent-sprite-forge-venv/`；已有可用环境不要重复安装。只有任务需要、允许安装且环境确实缺失时，才在项目根目录创建，不改系统 Python：

```bash
python3 -m venv local/agent-sprite-forge-venv
local/agent-sprite-forge-venv/bin/python -m pip install 'numpy>=1.26' 'Pillow>=10.1,<14' 'scipy>=1.11'
```

Windows PowerShell 需要单独的 Windows 环境，不能直接运行 WSL 的 Python；已有可用环境同样优先复用：

```powershell
py -3 -m venv local\agent-sprite-forge-venv-win
.\local\agent-sprite-forge-venv-win\Scripts\python.exe -m pip install "numpy>=1.26" "Pillow>=10.1,<14" "scipy>=1.11"
```

需要视频处理时，先按 [FFmpeg 官方下载指引](https://ffmpeg.org/download.html) 准备含 `ffmpeg` 和 `ffprobe` 的版本并加入 PATH；使用透明 WebM 或 H.264 导出还需要相应编码器。是否可用应在获准执行的任务中检查，不能沿用旧会话的缺失／成功结论；本次没有重新检测。需要时可运行 `local/agent-sprite-forge-venv/bin/python .agents/skills/video2dsprite/scripts/video2dsprite.py doctor`，它不同于可能消耗额度的外部路由验证。SVG 的可选渲染器按上游 `codeart2d/references/rasterizers.md` 选择。

`local/` 已由 Git 忽略。以下命令以 WSL/Linux 环境为例；Windows 可将开头的 Python 路径换成上面的 `.exe` 路径。

**检查现有图集**：

```bash
local/agent-sprite-forge-venv/bin/python .agents/skills/create-game-assets/scripts/asset_report.py public/fx/FX_MING_CANDLE.png --require-alpha --json
```

**离线运行上游像素示例**：

```bash
local/agent-sprite-forge-venv/bin/python .agents/skills/codeart2d/scripts/render_pixelspec.py --spec .agents/skills/codeart2d/examples/slime.pixelspec.json --output-dir local/forge-example --variants base --preview-scale 4 --strict-qc
```

示例输出到 `local/forge-example/`，包含 PNG 帧、预览和检查结果。输出目录必须不存在；再次运行时改用一个新的目录名，不覆盖已有结果。这是用户明确试用离线代码绘图时的示例，不调用图像模型，也不是 A 的生产素材或本次已执行记录。

## 费用、素材和导入

- 图像/视频 API 和已登录的外部 CLI 可能收费或消耗订阅额度。**调用前必须得到用户对供应商及预算或额度的明确授权**；已配置密钥不等于授权。不要把密钥写入仓库、提示词或日志。
- 上游默认没有统一的费用上限。授权使用时先核实供应商和可用限额；不确定时只做不会发送请求的 dry-run 或本地处理。`.forge/` 是本地调用记录目录，已由 Git 忽略。
- `FORGE_MAX_PAID_REQUESTS=0` 可作为阻止付费 API 请求的额外限制；它不限制本地 CLI 的订阅额度消耗，也不替代事先授权。
- Forge 的通用导出目标不等于本项目的 Canvas 装配契约。图片或帧必须先核对当前实际加载格式、路径、alpha、尺寸、裁切、锚点、采样与时序；SVG 概念不能假定能直接作为微信运行纹理。现有 FX 使用 `public/fx/data.json` 和原 PNG 图集，由宿主帧循环合成；本次不重导出或替换。微信仍需目标基础库和设备上的实际验证。
- 工具代码授权不自动覆盖 AI 生成素材或参考图的权利。使用素材前记录来源并核查服务条款及素材授权。
