# 轻休闲体验优化总纲

日期：2026-11-18  
状态：方案内代码与定向内容改动已落地；工程检查和 Web Canvas 抽样已通过。仍缺微信开发者工具／真机和独立玩家试玩，不能记为整轮验收通过。待核实图鉴条目不计入当前完成率。证据见 [05 执行记录](05-实施顺序与轻量验收.md#本轮执行记录)；第3节为方案审读时的旧版基线，不代表现行统计。

## 1. 这次要做成什么

《穿越了这次我带大喇叭逆袭》按轻游戏来做：带一件现代家当，看看自己在明末会过成什么样，偶尔做个决定，遇见几件能记住的趣事，结束后愿意换件家当再来一次。

玩家不需要研究公式、背前置条件、规划几十年的最优路线。随手选也应该能看懂、能继续、有自己的故事。认真选可以得到不同结果，但不能把“不查攻略”当成惩罚理由。

本轮最重要的判断是：**读起来轻松，发生的事有点意思，前后别明显打架。**

这里的“不严格”是对历史细枝末节、策略平衡和文风配额放松，不是对扣钱、死亡、存档、年龄和收集资格含糊。

## 3. 本次核实的底座

当前生产目录为 `assets/resources/data/ming_end/`；客户端是 TypeScript + minigame-canvas-engine 的 Canvas 实现，面向 Web 和微信小游戏。本轮不恢复 Cocos，也不按旧制作文档中的 Cocos 路径改代码。

- 当前配置为617个事件、22条链、143项成就、36种死因；这些是配置总量，不是全可达保证。
- 8件配置家当中，当前开局池只有6件现代家当；旧蒙书、破碗没有正常获取入口。方案提出时其20项持卡成就计入图鉴分母，现按逐ID核查口径处理，历史记录仍保留。
- 一生最多5次重大选择；第十年出现可见过程的仿真仍要求至少一次，若此前因死亡结束则允许0次并单独统计。自动事件、自动检定和人生观察本来就是主体玩法。
- 既有400局报告中，活到第十年的样本有77.68%此后没有重大选择。这是节奏参考，不能直接等同“无内容”或“无聊”。四策略使用同一批种子，不是400个独立开局。
- 原方案审计对应内容指纹 `e0bc9db4f16fe7da115fe6af711dd121bd89b2ed7d5dc60e6fc0bbbed251d9d2`；当前配置与验证结果见 [README](../../README.md)，不得将旧指纹当成本轮结果。
- 本轮实际在390×844 Web Canvas走过自然开局、选卡、选择、年度推进和事业管理，至第三年；后期结论另结合既有轨迹和报告。不将其写成完整真人复玩或微信真机验收。

依据：[当前README](../../README.md)、[仿真汇总](../../local/late-life-final/final/four-strategies.summary.json)、[生产开局池](../../assets/resources/data/ming_end/pools.json)、[图鉴统计](../../src/game/presentation/CollectionProgress.ts)。

## 4. 对上一轮建议的调整

| 上一轮问题 | 轻休闲方向下怎么处理 | 这次不做什么 |
| --- | --- | --- |
| 后期缺少决定 | 先减少重复阅读和闪屏，让旧选择有好看的后果；只修有资格却进不去的机会 | 不追求每几年一次选择，不统一把终点拖到后半生 |
| 策略深度不足 | 保留“试试看、稳一点、先不干”等直观分歧 | 不增加资源账本、技能树、装备组合或复杂职业规划 |
| 高风险选项没收益 | 删除明显自损的菜单；少量真正冒险保留合理好处和简明危险提示 | 不为了死因数量保留一排送命按钮 |
| 文案不够有趣 | 写具体遭遇和人的反应，允许自然吐槽、少量网络梗 | 不把每句都写成段子，不以字数或梗密度考核 |
| 数值用途不均 | 改少数体验差的节点，普通失败能继续生活 | 不追求六件家当胜率、五维使用次数完全相等 |
| 重开动力弱 | 图鉴能完成，下一局有个轻量想法，传承只留有用选项 | 不做每日任务、签到、体力、长期数值养成 |
| 内容量大 | 先处理已看见的低价值重复、闲置入口和死菜单 | 不再以新增事件数证明进度 |

## 5. 保留与减法

### 保留

- 随机身份、随机年龄和时代处境；选一件家当的简单开局。
- 三件推荐候选及免费换家当，不增加抽卡货币或收费刷新。
- 每年真实结算，轻点推进一年、按住连续；选择、死亡、后台及存储失败仍停下。
- 五维和真实D20作为后台规则；具体成功率可看，公式不用人人阅读。
- 失败、小倒霉、普通人生、遗憾和少见高光。轻松不等于人人富贵、次次成功。
- 家庭和事业的基本因果，已学会的本事不因中断凭空清空。
- 本机存档、图鉴、终局和一次性不累积传承。

### 做减法

- 去掉卡牌说明与附注重复的“检定+1”。
- 默认不展示限幅前修正、原骰下限等计算术语；详情仍能查。
- 合并同一事件实例被拆成多张的情境、检定和结果。
- 普通自动检定不反复占满屏幕；看结果为主。
- 不必反复提醒“不能包治、不能万能、不能替代某某”；仅在物品说明和相关风险处准确交代。
- 现代词条与家当合并展示，减少只有一件物品却分两页的空结构。
- 将重启移到二级入口，保留覆盖确认；主阅读面少一个容易误触的按钮。
- 取消新传承中的“指定家当”奖励，因为普通开局已经可以免费换；旧状态按04处理。
- 移除当前不可获取条目对图鉴完成率的影响，历史记录继续可查。

## 6. 对文字放宽，对大漏洞不放宽

允许一句“这回真没白忙活”，不要求每次检定都讲科学原理。允许小误会和荒诞遭遇，不要求所有古代人都按现代工作流程讲话。

仍不能出现这些情况：

- 四岁孩子独自带兵、主婚、掌管官署，却没有任何适龄解释或条件。
- 刚出生的孩子第二年结婚，去世的同一人又按活人参与新事件。
- 玩家没有接的差事自动扣大笔家资；刚选安全方案，直接触发该方案未提示的死亡。
- 文案说药已经用完，后面又无限取药；说交出手电，却继续默认拿着手电。
- 新玩家不可能完成的项目计入100%收集目标。
- 用新成就名覆盖旧死亡成就ID，让玩家的历史经历被改写。

修这些问题采用小范围条件、状态和文字修正，不新建完整婚育模拟器、物品耐久系统或经济模拟器。

1. [文案设计与风格规范](../文案设计与风格规范.md)：明确允许适量自然网络梗，限制重复免责声明；保留事实与风险要求。

3. [UI整体风格方案](../UI整体风格方案.md)：保留A浅纸漫画视觉，只同步阅读层级和入口变化。
4. [现代家当制作文档](../modern-relic-build-chains.md)：同步六卡分支、条件和现状，不再将旧版本条目数当现状。
5. [README](../../README.md)：在完成并验收后更新实际功能、图鉴口径和存档边界。

后续若要修改5次选择上限、增加主动提前结束人生、改变抽卡自由度或增加长期养成，那是另一轮产品决策，不夹带在本包实施里。首次重大选择前自然早逝的0次例外已按用户选择保留，不增加日常确认。
