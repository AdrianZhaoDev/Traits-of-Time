# 01｜玩法数值与人生节奏

状态：本册指定的六家当突破菜单、检定与事故调整已写入生产配置；跨册界面与目录以各自实现和 README 验证记录为准。下表保留原方案对照，不把单阶段概率当作真实玩家体验结论。

## 1. 核心取舍

- 自动故事继续占主体，一生最多5次重大选择；第十年出现可见过程的仿真要求至少一次，此前自然死亡可为0次并单独统计。不给日常加确认，不为降低“后期零选择率”强塞菜单。
- 玩家选方向，游戏替玩家展开已同意的普通进展；重大花费、主动涉险、换事业仍由玩家决定。
- 选得不完美也能继续。有时多赚一点，有时闹个小笑话，有时错过高光；不要求每次都结算成胜负。
- 保留死亡和遗憾，但普通误会、读书、修补不轻易接突然死亡。历史灾害、实际病弱和明确选择的涉险另当别论。
- 六件家当各有好看的故事即可，不要求胜率相同，不设计多套资源和职业配装。

## 3. 选择菜单做减法

### 3.1 菜单怎么留

优先让玩家一眼看到两到四种意思不同的行动：认真试试、稳妥帮忙、少量明确涉险、这次不接。不是每个事件都必须有四项，也不是把所有选项统一改成这四句话。

同一年、历史线和架空线的互斥方案不算重复内容，显示时不要把不适用的整套历史说明铺满。因当前属性暂不可选、但对本局有意义的方向仍可显示简明原因。安全与退出如果后续确实不同就都留；如果效果、后续与文字都同义，合并配置及引用，而不是把两颗同义按钮保留下来。

每个保留选项只需让人明白：要做什么，可能得什么，明显会损失什么。无需让每个选项都承担多年复杂分歧。小选择也可以有趣，但不能占掉一生唯一转向却只回一句“你离开了”。

### 3.2 玉米突破：从七项配置减到四种可用行动

目标事件：`E_MOD_CORN_BREAKTHROUGH`。历史与架空推广互斥，以下保留本轮改动对照。

| 选项ID | 具体处理 | 规则与结果 |
| --- | --- | --- |
| `corn_promote` / `corn_late_promote` | 保留，显示为“和乡邻试着推广”一类动作；两时局仍独立分支 | 保留实践前情及才干、人脉门槛；检定按第4节调整。历史失败家资-2改-1，人脉-1保留；架空失败仍人脉-1；保留SETBACK和既有成功/大成功标记 |
| `corn_safe` | 保留稳妥接济 | 人脉+1、`F_MOD_CORN_MODEST`及原后续保留，不为平衡强加成本 |
| `corn_trial_risk` | 改为有实际目的的“冒险送种到邻村”，保留现有试种/护粮前情和历史线限制 | 仍入`E_MOD_CORN_TRIAL_hazard`，DC16不动；成功由家资-1改为人脉+2，结果写送到种粮且获得认可；失败保留既有遇抢死亡及THEFT标记。选择前直说“送到可得人脉+2，途中可能丧命”，不称安全近路 |
| `corn_store_risk`、`corn_relief_risk` | 删除主动争辩免水、卖光口粮两项及独占阶段 | 不把纯自损强塞成玩家必选事故；死亡定义和旧记录保留原义，停用收集按第6节与04处理 |
| `corn_withdraw` | 保留不再推广 | 保留退出标记与后续限制，不能改成仍能照常突破 |

历史、架空可用项不必完全一样。独行涉险入口采用本轮明确门槛`age ≥ 18`；这是自愿危险分支的内容限制，不改全局成年身份线。幼龄玩家保留推广协作/稳妥/退出等适龄路线，不让家人陪同的文案替孩子承接独行涉险。该新送种结果属于玩法重写，必须连同效果一起实施，不能仅换选项名字。

### 3.3 医药突破：四项已经够用

目标：`E_MOD_HEALER_BREAKTHROUGH`。

- 保留`spread`、`safe`、`use_course`、`withdraw`。分别是推广照护、留在本地、交出整板药、退出协诊；药的交付是这件家当特有的简单取舍。
- 删除`delay`和`showoff`两项及无其他来源的独占阶段。不要求玩家先选择延误求医或取回药物独走夜路，才能收齐普通成就。
- `spread`现有失败只有人脉-1，不必标成与致死涉险相同的高风险；改普通风险，提示“没谈成会损人脉”，不暗示治愈保证。
- `use_course`继续移除COURSE_AVAILABLE、写入COURSE_USED。交药后仍有手册、仍能协助照护，不能自动再发一板药；不得因简化自动替玩家交药。
- 不新增病种、剂量、药品库存等系统。临床过程保持概括，不提供现实用药指导。

### 3.4 手电突破：普通查证不再一失败就丧命

目标：`E_MOD_FLASHLIGHT_BREAKTHROUGH`。

- 保留才干查证与体魄查路两种方向、交记录、少量真实涉险及退出。两种属性都可用时可有五项，不为凑四项隐藏有效策略；显示必须清楚。
- 历史`break_intelligence`、`break_physique`失败从死亡改为人脉-1；文字明确结伴核查未果。其风险改普通，与架空`late_intelligence`、`late_physique`的轻损失一致。历史和架空背景仍分别写，不机械复制整段。
- 删除`flashlight_claims`、`flashlight_misstep`及其独占逃生阶段。吹透墙和独闯暗沟不作为收集必经的送命题。
- `flashlight_robbery`增加`age ≥ 18`，保留自愿追贼；现有成功只重复线索标记，增加人脉+2，仍写避开同伙、返回巷口并与巡丁核对脚印，不改成打赢抢灯者或破获全部旧案。现有失败死亡保留，危险在选择前可见。继续使用现有逃生阶段和DC17，不另加一轮骰子。
- 退出文案核对是否实际交出物品：引擎目前仍持卡，若只是停差，应写“收灯不再追查”而非“交灯”，不为修一句话新增物品转移系统。

## 4. 难度定点调整：减少“够资格了还反复卡门槛”

以下作为首轮可实施参数，不是已经证明最优的平衡结论。只作用于表中节点，不对192个检定全库替换。保留前情、身份合理性、药物已用尽和预算等事实门槛；自然1仍失败、大成功仍少见。

| 家当与节点 | 调整前 | 本轮改法 | 目的 |
| --- | --- | --- | --- |
| 玉米`promote/promote_late` | DC24，原骰下限10，才干≥12、人脉≥8 | DC20，删除此处`raw_minimum`，其余事实条件保留 | 正常走完种田故事后，推广更容易成功 |
| 医药`S_SPREAD` | DC24，原骰下限10，才干≥12、人脉≥8 | DC20，删除此处原骰下限 | 未成功仍可留在本地，不造成药物神效 |
| 手电四个正常查证/查路阶段 | DC22，原骰下限10，主属性≥12、人脉≥8 | DC18，删除此处原骰下限 | 查案高光更常见，失败不是被迫退场 |
| 计算器`breakthrough` | DC24，原骰下限10，才干≥12、人脉≥10及前情 | DC20，删除此处原骰下限，人脉门槛10改8 | 少一道同质门槛，仍须已有路线和账目事实 |
| 胶水`E_MOD_SWISS_BOOK/review` | DC18，原骰下限10 | DC18不变，删除此处原骰下限 | 给普通传艺一次较顺的体验 |
| 胶水`E_MOD_GLUE_CRAFT_CHALLENGE/glue_craft_test` | DC11却另有原骰下限10，体魄与才干均≥12 | DC18并删除原骰下限；体魄门槛改8、才干12保留，匠作前情不动 | 取消隐藏硬掷骰墙，不因为DC数字变大误判为变难 |
| 打火机`breakthrough` | DC24，原骰下限10，体魄≥14、气数≥10及行伍/护火前情 | DC20，删除原骰下限；体魄门槛14改12，取消普通入口的气数≥10，其他前情保留 | 气数是运气，不该成为普通护粮路线的必修课 |

同一准入条件若同时写在事件根条件、选项条件和不可用说明里，必须同步修改，并更新图鉴提示；只放宽按钮、却被事件根条件挡住，不算完成。其他前情、燃料耗尽、药物交付和选择预算条件不变。

概率对照来自现有 `previewCheck` 枚举 20 个骰面，比较原配置与本轮参数；这是单阶段计算，不代表整条路线成功率。

| 场景 | 固定输入 | 调整前成功率 | 调整后成功率 |
| --- | --- | ---: | ---: |
| 玉米/医药/计算器相应阶段 | 才干12、气数3、匹配家当+1、配置修正0 | 50% | 70% |
| 手电正常查证 | 主属性12、气数3、匹配家当+1、修正0 | 55% | 80% |
| 胶水验样 | 才干12、气数3、匹配家当+1、修正0 | 55% | 80% |
| 胶水传图 | 才干12、气数3、匹配家当+1、修正0 | 55% | 80% |
| 打火机同输入对照 | 体魄14、气数10、匹配家当+1、修正0 | 60% | 85% |

打火机新门槛体魄12、气数3时为70%，旧版该输入不能进入选项；不把“不可选”写成0%成功率。这些是单阶段概率，不是整条路线成功率。最终通过与否以实际角色当时属性计算；不设全局“必须80%”指标。

不削弱手电认错鸡爪印后的才干+2、人脉+1；这种失败有收获的设计适合休闲玩法。若玩家觉得“失败怎么还加数值”，在结果里写清补救或另有收获，而不是强行加惩罚。

## 5. 普通小意外改轻，真正危险保留

已核实`E_MOD_CALCULATOR_MISUSE`是低才干时可能自动遇到的黑屏误会，失败会跌下栈桥死亡。该分支没有玩家主动涉险，且与黑屏的小误会不相称。

首轮建议保留触发、真实检定及DC12，把该阶段失败改为“解释没讲明白，你先收好计算器离开，人脉-1”，删除该分支死亡和死亡标记，不触发重伤、重掷、保底或新任务。成功解释清楚的分支不再加“以后不夸口”的训诫。对应死因若失去最后路径，转历史目录；计算器相关成就是多条件`any`，先核实其余真实来源，不一并误删。

对其余六卡自动事故只做一轮定向清点：凡起因只是普通使用、失败却直接死亡的，逐项判断。不是所有死亡都要删除，也不是给所有事件加二段救援。真实灾害、病弱和明确承诺的职业危险保留；发现与本定位相反的案例，用同样的小损失修订并列明ID，不批量替换`death`效果。

本次定向清点中，`E_MOD_LIGHTER_MISUSE` 的暖手故障失败改为停用火机、体魄 -1（受数值下限限制）；旧死因 `D_MOD_LIGHTER_GAS_BURST` 保留历史记录，不计当前目录。误饮、误用胶水仍按实际救治阶段处理，坡边耍刀仍为明确危险情境；未批量删除死亡。

## 7. 后半生：保留生活，少一点重复确认

不把77.68%的后期零选择率当硬指标。本游戏可以有很长一段自动人生；真正要减少的是“同一句又来了”“小事被说得很重大”“不知道还在等什么”。

### 7.1 先改呈现，不盲拆调度组

- 旧年份按03折叠，完整年表可回看；每年仍逐条结算保存。
- 家当故事仍按现有1/3/6或1/3/6/8节点推进，不统一拖慢。
- 有活跃事业时只提示最近进展年，没有事业时不造一个空任务。
- 连续推进在重大选择、死亡及异常处停止；不自动代选，不新增一键直接结算余生。

### 7.2 首轮指定处理的重复

`E_LIFE_FICT_CLAN_TEMPLE`当前每隔若干年还能重复“整理旧账发现书虫”，且没有效果。将其`max_occurrences`从null改1，保留现有触发条件和一次完整小趣事；不凭空补新变体或奖励。其他反复小事按真实长局阅读逐条列清单，不以所有重复都错误为由全库限一次。

粮铺改开门日、掌柜留货等弱兑现：先保留事件、标记和后续组，只写成普通小事；不称“重大兑现”，不连续弹庆祝、加成就或另要点击。初次只说新安排，回来时只说实际结果，不再解释两遍。不把相隔几年的两条事件强行合为同一日，也不通过显示层把旧约定变成新成果。

若再做配置层删减，必须同时处理所在follow_up组的fallback、`after_group`、时间窗、标记读写和后续可达性；不能只删第一条让后续永远等不到。本轮默认优先显示减法，不以砍掉166条后续为目标。

### 7.3 年龄造成的卡住要修，不一律加速

幼年学习沿用已有陪同或代办事实；无依据不临时补出亲属，成人独立行为需要实际年龄条件。高龄路线尽早有一个小结果，不保送大成功。保留已有晚年份适配，不把“开局晚”误写成“年龄老”。具体逻辑修补在04；不以读取随机寿命上限替玩家精确规划最后一年的方式安排剧情。

## 8. 实施落点与验收

主要修改[events.json](../../assets/resources/data/ming_end/events.json)、[achievements.json](../../assets/resources/data/ming_end/achievements.json)及对应死因目录、[AchievementHints.ts](../../src/game/presentation/AchievementHints.ts)。菜单或能力说明改变时同步[chains.json](../../assets/resources/data/ming_end/chains.json)和[cards.json](../../assets/resources/data/ming_end/cards.json)。本方案不需要全局改`DiceResolver`或增加新数值系统。

后续执行应能回答：

- 新玩家读一个选择就知道要干什么，不需要先打开公式。
- 表中普通检定按实际预览得到对应概率，失败后果和风险标签一致。
- 玉米/医药/手电减项后每个合法开局仍有真实可用方向，选择预算没有重置或超额。
