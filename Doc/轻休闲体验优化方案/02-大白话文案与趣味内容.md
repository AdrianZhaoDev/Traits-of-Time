# 大白话文案与趣味内容方案

## 这份方案怎么用

本文件保留方案审读时的依据和示例；本次已对六件现代家当、指定事件及事业承诺进行定向修订，示例不保证与最终配置逐字相同。下文涉及的原分支数据用于解释修改前的原因，实际规则以生产配置和文末实施记录为准，不代表全库已经逐条检查。内容作者先读完整事件、各选项、阶段和效果，再决定保留或修改；不能为了凑趣味改掉结果。玩法节奏见[玩法数值与人生节奏](01-玩法数值与人生节奏.md)，家庭、幼年与后期依赖的逻辑修补见[图鉴重开与逻辑修补](04-图鉴重开与逻辑修补.md)。

目标是让人顺着读完一生：发生什么、你做了什么、后来怎样。自动故事是主菜，重大选择少而有分量；不用每条都有梗，更不用每条都讲道理。历史背景服务故事，不要求玩家做考据题，也不凭空捏造历史或道具效果。

## 写法：让事情自己有意思

1. **说人话。** 用“扫院换借书”“到亮处试算”代替抽象总结；动作和对象说清楚，结果只写这次真的发生的事。普通情节自然短一点，重要选择把代价和后果讲完整，不设字数、笑点比例或单行硬指标。
2. **笑点来自原有遭遇。** 鸡爪印认错、算账时一时看反，都可以轻轻写出窘境；“白忙活”“熟练得让人心疼”只作语气示意，不批量复制句式，不替玩家嘲笑别人。允许平实、遗憾和紧张，不在死亡、灾难、病患或任何群体身上找乐子。
3. **别把事件写成课堂。** 道具限制放在使用它、容易误解它或确有风险的地方；一般生活事件不反复叮嘱“要谨慎”“不能万能”。结果不追加一段品德总结，不把脚本中原有的尝试写成自作自受。
4. **分清各处职责。** 情境说眼前的事，选项说动作，选择前说明必要成本、重要风险和不可逆后果；结果说实际发生了什么。不要靠删风险去重，也不要清空字段遮掩显示重复。自动事件不是玩家主动选择，不能补写成“你选择冒险”。
5. **小孩和家庭先说眼前事实。** 例如原事件已有家人代读，就写“家人念给你听”，没有家人在场的依据就不要临时补出一位。关系变动、年龄不合理等大漏洞由04处理，不通过换个称呼遮住，更不在本方案新增监护人状态系统。

### 网络梗怎么用：不懂梗也能看懂事

采用玩家平时会说的轻口语，如“白忙活”“翻车”“没白折腾”“这下省事了”。偶尔用一处就够，下一条可以完全平实；不设梗密度，不把全库改成同一种吐槽声线。过时后删掉梗，原句仍应讲得通。

| 已有遭遇 | 可选的轻松版本（语气示例） | 不能丢的事实 |
| --- | --- | --- |
| 手电认错鸡爪印 | “查案先翻车了：你认错了鸡爪印。承认后重新描好鞋印，邻人点头认可。” | 有补救、有线索和属性收获，不是白忙一场；“翻车”可删，后面的事实仍然完整 |
| 读书失败却扫院练了腿脚 | “字还没认全，体能训练倒是没落下。你又扫了几间屋子，腿脚练得更好了。” | 才干没有增加，体魄+1；不是考取功名 |
| 胶水拼回瓷碗 | “碗是拼回来了，吃饭还得换一个。” | 只能当摆件，不能暗示可盛饭或承重 |

这些都是可挑选的语气，不是三条必须照抄的模板。更常用的还是普通话：“你把账算清了”“这次没谈成”“邻居来借灯了”。不追热搜，不加需要解释的缩写，也不用“赢麻了”“老登”等词替代具体人物和结果。

| 家当 | 卖点与该留内容 | 该删的重复 / 可用语气示例 |
| --- | --- | --- |
| 高产耐旱玉米良种 `CARD_MODERN_CORN` | 小块试种、邻里合仓、拿记录商量种法；种子有用，但要水、时间和人照看。 | 只在试种、推广等相关处保留需要浇水的提醒，不在每年反复念一遍。示例：“先种这一小块，看看长得怎么样。” |

| 手摇发电强光手电 `CARD_MODERN_FLASHLIGHT` | 照见线索、轮流摇灯，亮处看清和查明真相是两回事；保留误认鸡爪印的尴尬与补救。 | 不在每个夜景里都复读摇累了要休息；查案时才说光照不等于证据。示例：“照是照清了，还得问问邻居。” |

| 防风打火机与醒脑油 `CARD_MODERN_LIGHTER` | 赶路时备火种、准备干料、教人轮班；`E_MOD_LIGHTER_OLD_WHEEL` 中旧火轮还可画成保养图。 | 燃料和备火只在使用或交接相关处点到，不每遇一个人就解释一遍。示例：“火种备好了，轮到你歇会儿。” |

## 五组可直接交给作者的改稿

### 1. 手电：认错不等于一无所获

**依据：** `E_MOD_FLASHLIGHT_EVIDENCE` 自动事件，米铺丢粮，灯照到鞋印；`evidence_check` 成功找到偷粮线索，才干+3、人脉+3。失败是认错鸡爪印后承认并重描鞋印，仍得才干+2、人脉+1，且两支都写入同一线索标记。

**情境→动作→结果示例：**“米铺丢了两袋粮，后门留下半截印子。”→“你摇亮手电，描下印子，再问邻居。”→失败时“你先把鸡爪印认错了，赶紧承认，又把鞋印描了一遍。邻人点了点头。”成功时“鞋印描好了，邻居的话也帮你找到一条线索。”

**直接改文字：** 按现有失败结果写出补救与认可，别写“白忙一场”“什么也没查到”或已经抓到贼。印子、邻人的反应都来自该分支，不另加奖品；线索的后续意义仍以原标记使用处为准。

### 2. 计算器：黑屏不是道德惩罚，差额不是定罪

**依据：** `E_MOD_CALCULATOR_MISUSE` 为自动事件：低才干且持卡时可能出现，人群误把黑屏当坏兆头，`S_MOD_CALCULATOR_MISUSE_ESCAPE` 成功到亮处试算、解释误会；失败在人群拥挤的栈桥坠落丧命。另一个自动事件 `E_MOD_CALCULATOR_CORRUPT` 发现多出三袋粮，结果只是把工钱记录、粮袋和旧签单摆在一起核实差额。

**调整目标的情境→动作→结果：**黑屏：“屏幕突然没了字，旁边的人有点慌。”→“你到亮处试算，想把误会讲清。”→成功“屏幕又亮了，人群听明白了。”失败“你没能解释清楚，只好收起计算器离开。”失败人脉-1。三袋：“工钱和粮袋对不上，多出三袋。”→“你拿出旧签单一起核对。”→“差额核实清楚了。”

**修改边界：** 不写“炫耀遭报应”，不把三袋差额写成查获贪官、追回赃款。黑屏失败效果与文案已同批改为人脉-1，并移除该分支的死亡及死亡标记；保留旧死因定义供历史记录识别，不把旧死亡经历改写成新轶事。

### 3. 读书：免费不等于不用付出

**依据：** `E_SOC_YOUTH_APPRENTICE` 的 `study_path` 启动 `CH_STUDY`；事业说明为不收费用、扫院换借书、两年自动学习，最终检定失败或流离会中断，身份不变。`E_CHAIN_STUDY_1` 成功认字、才干+1；失败有些字认错，又扫了几间屋子，体魄+1。

**情境→动作→结果示例：**“书铺和工坊都招人，学本事不要钱，但要花两年。”→选项“扫院换借书”→“你开始借书学读写。”第一年失败：“有些字还认错，你又扫了几间屋子，腿脚倒是练到了。”

**直接改文字：** 选择前仍要说明两年、最终检定和这次人生转向只能选一次；事业承诺里的中断、退出和身份信息不可丢。失败不是没学到任何东西，也不是考中；显示层若同时拼出重复承诺，由03处理，不靠删除必要信息解决。

### 4. 玉米：高风险得先改玩法，不能换词洗白

**依据：** `E_MOD_CORN_BREAKTHROUGH` 中，`corn_trial_risk` 走险巷：`E_MOD_CORN_TRIAL_hazard` 成功仍损失家资1，失败死亡；`corn_store_risk` 的争辩支线成功赔粮、家资-1，失败死亡；`corn_relief_risk` 卖口粮支线成功亏本、家资-1并获得准备等标记，失败死亡。普通推广 `promote` 成功和大成功另有成果，失败家资-2、人脉-1；架空 `promote_late` 失败只扣人脉1。平价接济和停止推广另有各自条件。

**修改前的危险分支：**“你背着种粮走近路，巷口有人拦路。”→“你设法脱身。”→成功舍出粮食、失败丧命；旧选择需要提示脱险也可能损失家资。这是修改前依据，不是当前送种分支的结果。

**本次落地：** 删除`corn_store_risk`、`corn_relief_risk`及其独占阶段；`corn_trial_risk`改为成年人自愿送种，成功人脉+2、失败仍可能丧命，选择前列明收益和致死风险。历史推广失败家资-2改-1，人脉-1保留；历史及架空推广检定改为DC20并去除原骰下限。稳妥接济、正常推广和退出仍保留。旧死亡成就保留原ID和原义，新成就使用独立ID。

### 5. 后期小事：不用隔几年再确认一遍

**依据：** `E_LL_ITEM_NEIGHBORHOOD` 是邻人告诉你粮铺改开门日；`E_LL_ITEM_RETURN_NEIGHBORHOOD` 依赖前者标记，之后再次说赶上开门日，结果把前标记换成后续标记。`E_LL_RETURN_FREE` 则在另一路中隔着后续组确认铺子仍留货。它们不是同一个事件链，但都值得检查“约好一件小事，多年后只是确认约定仍有效”的重复感。

**现状口语示例：**“粮铺换了开门日，邻人顺口提醒了你。”→“你记下日子，省得白跑。”留货支线可写“掌柜还按说好的价留着货。”不虚构买到了什么或多赚了钱。

**本轮按01先减阅读负担：** 保留两次经历各自的年份、事件和标记，初次只写约定，后续只写实际结果；不把相隔数年的两事拼成同一天，不升级成商会大事，也不为后期凑选择。若以后要删触发、合并配置或改变标记，先核对follow_up分组、fallback、窗口及全部依赖，再按04处理存档与指纹；单删显示文字不能冒充完成。逐年结算保持不变。

## 成就、规范与落地边界

**成就写法。** 现代卡在单朝代仍按现有规则维持每卡10项、N/R/SR/SSR为3/3/3/1；这是配置完整性，不是要求每句押韵或每级都更夸张。先对照成就条件、事件效果和实际解锁路径，再写易区分的名称与一句短评。死亡或灾难如实、克制记录；稀有不等于编造身份、历史影响或奖励。纯文案不改ID、条件、priority、category；改名同步玩家可见引用。

**正式规范：** 已同步[文案设计与风格规范](../文案设计与风格规范.md)，明确轻松阅读、情境／动作／结果分工、适量自然网络表达、相关处保留物品限制，以及按事件ID区分纯文案与规则变更。保存、Canvas可读性、安全边界和校验条款保留。

**正文涉及的生产范围：** [`events.json`](../../assets/resources/data/ming_end/events.json) 的情境、选项、各阶段和结果；[`cards.json`](../../assets/resources/data/ming_end/cards.json) 的名称与说明；[`chains.json`](../../assets/resources/data/ming_end/chains.json) 的事业承诺、完成和中断；[`achievements.json`](../../assets/resources/data/ming_end/achievements.json) 与 [`deaths.json`](../../assets/resources/data/ming_end/deaths.json) 的名称和说明。图鉴历史项及卡牌加成显示需结合 [`src/view.ts`](../../src/view.ts)、[`src/home.ts`](../../src/home.ts)、[`src/game/presentation/AchievementHints.ts`](../../src/game/presentation/AchievementHints.ts) 的真实实现检查；不修改归档或生成副本。

**实施约束：** 纯文字改动保留ID及引用、条件、概率、效果、阶段和档案；文案会改变内容指纹，按项目既有内容装载与指纹流程处理，不能篡改旧记录绕过匹配。规则或触发调整单独列项，与01、04对齐，不混成“润色”。不批量造新事件。
