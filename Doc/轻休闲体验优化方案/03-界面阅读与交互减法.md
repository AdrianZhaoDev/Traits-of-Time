# 03｜界面阅读与交互减法

> **状态：界面实现已落地，验收仍有限。**沿用浅纸漫画 A「爆笑开播」风格和现有 Canvas 客户端；下文的旧现状是制定方案时的基线，示例文案不代表生产结果。具体检查及未覆盖范围见 [README](../../README.md)。玩法节奏见 [01](01-玩法数值与人生节奏.md)，图鉴、传承和兼容见 [04](04-图鉴重开与逻辑修补.md)。

## 一、已核实的落点与边界

- 当前是 TypeScript + minigame-canvas-engine 的 XML/Flex 和 Canvas，目标是 Web 与微信小游戏，不是 Cocos。界面主要在 [view.ts](../../src/view.ts)、[home.ts](../../src/home.ts)；控制、弹层栈和存储在 [controller.ts](../../src/controller.ts)，真实输入与长按在 [renderer.ts](../../src/renderer.ts)。
- `cardOffer` 同时输出 `card.description` 和 `check_bonus`；部分卡描述已经写了同一个检定 +1，存在重复呈现。`optionDetails` 会把风险、概率、修正和原骰门槛一起铺开。事业管理目前将现代词条、家当分为两个标签。
- 主按钮当前是「推进一年 · 按住连续」。`finishCurrentYear` 用 `GameSession.advanceToDecision` 在本年度完成自动阶段，真实命令逐项保存；`syncRequiredOverlay` 又会为待处理 stage 建立必需弹层，自动检定显示有短暂等待。续档 `restoreLoaded` 明确暂停。以上是源码事实，不等于已完成本方案。
- `LogParser.parseBatch` 已尝试聚合，但使用连续同文去重、来源 ID 和当前待合并项；`effects` 合并后即落条，后续阶段可能成为另一条。不能说现在已按实例完整聚合。`LogData` 中 event/option/dice 有 `event_instance_id`，effects、achievement、death 并没有；需解决真实关联，不能把 `source_id` 假当实例 ID。
- `ChainInstance.next_due_year` 是已有日期，可能为 null，且有多条活跃事业。`EndingReport` 和原始日志提供事实；目前结算是统计、死因、成就等，尚非本方案三段回顾。

## 二、逐面怎么减

### 1. 首页：让开始和继续更好找

保留正式游戏名、A 风格、已有插画与「带一件现代物品过一生」的说明；主操作只依据真实存档显示「我要穿越」或「继续人生」。图鉴、声音、统计收在次级区，收集进度可移至图鉴，不在开局按钮前堆多行百分比；有传承只提示「下局可选一项小加成」，具体在传承页选。重开进入次级入口，并保留现有覆盖确认；损坏、不兼容、只读、存储不可用及本机数据提示仍完整可见。只读时绝不显示能开局的假按钮。

### 2. 身份与家当：先说这一局像什么

身份页先读年份、年龄、身份及地区，再把阶层、传承等排在后面；不因追求一屏而隐藏或截断。家当页每张卡按「名称 → 一句故事方向 → 实际作用」排，例如手电可说「带着手电，可能遇到夜巡和找线索的故事；夜巡检定有加成」。这只是方向，不保证出现，更不保证成功。

统一卡说明的事实来源：先核对描述与 `check_bonus`，同一项 +1 只出现一次；若说明没包含加成，再补真实效果；如果是不同标签或限制则分别保留，不按文本相似度盲删。保留稀有度、候选选中状态、免费替换、最多三个候选、确认后仅带一件且不可更换；不把定向候选说成额外一件。

### 3. 主阅读：本年一段一段看清

保留年号、年龄、五属性和家当入口，缩减重复身份、修饰标签与间距，为故事留空间。按实际 `calendar_year` 组织：当前年默认展开，旧年份可折起、逐年重新展开；折起只影响视图，不删日志、不跳过引擎年份，也不改变原本有多条事件的年份。玩家手动向上读时不抢回滚动位置；点「查看最新」才定位最新结果。多次自动推进也不能把未读结果吞掉。

当前目标至多一行：从真实 `status === active` 且 `next_due_year !== null` 的事业中，按最近到期年及稳定的实例 ID 决出一条，例「正在学手艺 · 下次进展 1635 年」。若已到期但尚未处理，写「等待本年进展」，不伪称一定会成功；点击可进入现有事业管理。无符合条件的链就不显示目标，不捏造任务。多个链的其他信息仍可在管理页查。

**故事合并实施契约：**在 [LogParser.ts](../../src/game/presentation/LogParser.ts) 和控制器日志转换中，以事件实例为边界，将同一实例的起因、选择、各次骰子及结果按 seq 顺序组成一个可读故事块；多阶段结果应追加，不能后一个覆盖前一个。同一个 event ID 在不同年或同年不同实例必须分开，文字完全相同也不能因此删掉。先核对各命令的日志生成路径：event/option/dice 可直接关联实例；无实例字段的 effects/achievement/death，只有在已证明同一事务及事件上下文时才能关联。必要时为新日志补明确关联并规划存档格式/回放版本兼容；旧日志信息不足时保留独立项和顺序，不跨实例猜配。不要用随机 ID 或事件 ID 当聚合键；保持原骰、具体结果、属性变化、成就和死亡可查，不能因去重丢内容。展示层显示结构化变化时也需与正文去重，不是删掉重要变化。

### 4. 抉择与检定：先看行动和后果

`optionDetails` 拆成首层必要信息和可展开的「检定怎么算」。每个选项先写动作，再写已知直接成本、可判断的收益方向和重大风险；不可用时显示真实原因。示例：「修好屋顶｜花费家资 1；可能改善住处」，数字和因果须逐项核对，不能把可能当必得。选项开始事业、不可退费用、耗时、会死亡或后续可能丧命等，必须在点击选择之前可读，不能只藏进公式详情。概率可留首层简短呈现；限幅前后、属性、气数、DC、原骰下限、特殊大成功率和自然 1/20 等详细规则默认折叠但可展开，数据仍取引擎预览，不重新猜算。

只隐藏配置明确排除当前时局的选项；其余选项继续使用引擎的可用状态、真实禁用原因和风险。组合条件中不能证明排除当前时局的，不在显示层猜测隐藏。

普通自动事件的结果一经命令保存并返回就出现在故事区，不再让玩家点一次「查看结果」。自动 stage 不反复建立、撤销整屏弹层：当前年内使用稳定的行内「正在检定」状态，完成后直接展示真实骰点与结果；详细检定可主动展开。遇到需要玩家做决定的 option 仍停在必需抉择界面，绝不能自动代选。恢复到尚待 stage 的旧存档时先停住，提供明确「继续检定」；用户主动继续才执行，不因恢复界面而重掷或私自推进。不同自动阶段、死亡、保存失败和后台切换均保留原始停下/恢复语义，不能为了消闪而绕过真实 `resolveStage`、子命令写盘或回执。

### 5. 管理、重开、结算

管理保留「事业」「家当」「生涯成就」即可，现代物件与其他实际持有物件在同一「家当」页呈现；按 `player.cards` 真实内容列出，不制造未持有物品。事业退出仍保留选择目标、已付费用不退及已学本事保留的确认提示。局内底栏把重开移入管理的次级操作；选择「重新开始」后仍走控制器现有检查和不可误触的二次确认，明确将覆盖本机当前人生。决策弹层进入管理时返回必须回到同一决定，不得丢待选项。

结算首屏先说这段人生的真实经历，再展示死因、成就和下局建议；细项可折叠但不能删除实际结果。三段如何取材、记录不足如何如实显示，按 [04](04-图鉴重开与逻辑修补.md)；「再来一局」仍经过存档覆盖和传承的实际判断。

## 三、输入、尺寸及停机条件

单击推进一年；按住连续由现有 `seal` 手势串行发出逐年动作，只在上一年保存确认且 READY 时继续。松手、手指移出/取消、打开弹层、进入重大选择、死亡、保存异常、切后台或失焦即停止连续授权；恢复时保持暂停，需要玩家重新操作。既不一次提交跨多年，也不因加速隐藏每年的真实结果；键盘已有操作与触摸不能互相抢焦点。

布局继续使用项目 750 逻辑宽及真实视口换算，尊重安全区，短屏优先减少装饰和空白，再让正文及警告完整滚动；不压小字、不裁关键风险。按 [规范](../文案设计与风格规范.md)：正文目标约 16 CSS px，非关键短标注至少 12，重要警告目标 13–14 以上；点击区至少 44 CSS px、相邻约 8。折叠控件有文字、展开状态和键盘可操作性，不只靠颜色表达风险。

## 四、实施顺序与验收边界

1. 先整理 `view.ts`/`presenters.ts` 信息分层与卡牌去重，再改 `home.ts`、管理入口及重开确认；沿用 `controller.ts` 权限与覆盖保护，不另设存储机制。
2. 明确 `LogData` 关联和历史日志回退后改 `LogParser.ts`、controller 聚合及按年折叠；再处理自动 stage 行内显示、恢复暂停，最后接入 renderer 手势与短屏滚动。若调整日志持久结构，先按 [04](04-图鉴重开与逻辑修补.md) 评估版本和指纹，不伪装成兼容。
3. Web 与微信均需检查首页→身份→换卡→普通事件→重大抉择→自动检定→管理→结算，并核对选择前成本风险、日志顺序、续档和长按停止条件。最终 Web 构建已在两种竖屏和短横屏抽查；CDP 模拟触屏长按、松手和拖动，不等于实体设备。微信验收仍缺，详见 [README](../../README.md#轻休闲方案收尾验收)。
