# 05｜实施顺序与轻量验收

状态：代码与定向内容已落地，工程检查和最终 Web Canvas 抽样已完成；剩余现场验收见文末执行记录。旧版工程记录、方案审读试玩及浏览器模拟触控不能替代本轮真机或真人验收。

## 1. 实施方式：分批能玩，不一口气重写

本轮以“少改系统，先让现有游戏好读好玩”为原则。先解决错误承诺和阅读阻碍，再改关键分支，最后清理长局。生产文件各批由一个集成负责人合入，尤其`events.json`、`achievements.json`不能让多个作者各自覆盖整份文件。

内容作者按事件ID交完整分支改动；界面开发消费真实配置和引擎预览，不另外存一套成本或成功率。每批完成后执行一次对应验证，失败则修正原因，不删断言、不隐瞒失败、不反复重跑只求绿灯。

## 2. 建议的四个实施批次

### 批次一：收集说真话，先把页面读轻

范围：

- 04中的原生书、碗不可达条目与历史记录区分，统一首页、图鉴、结算的分母。
- 03中的卡牌卖点顺序、重复+1去重、选择公式折叠、家当管理合页、局内重开移二级。
- 04中的家资刻度展示，去掉数值后面的“两”，不改经济效果。
- 02中与以上界面同步的少量说明，保留准确成本和风险。

交付结果：新玩家能看懂家当用途，不用读完整公式；图鉴不再承诺当前无法收齐的目标；历史已收集项目不丢。

暂不接入：新成就、风险菜单调整、日志结构、自动检定执行流程。这样先得到一版可玩的阅读改善，不把全部风险混在一起。

### 批次二：六家当的普通路线更顺，纯自损菜单减掉

范围：

- 01给出的具体选项、阶段、门槛和DC调整，连同成功/失败/大成功结果一起修改。
- 六项明确的旧死亡奖退出当前目录，新奖采用新ID与真实条件；另核实计算器事故死因的其他来源。
- 02按新规则完成相应事件、成就、家当说明和事业承诺。
- 按04同步当前目录、旧记录显示、解锁提示，不留下停用入口指引。

交付结果：玉米、手电仍可自愿涉险，但不是成功也只亏损；医药不靠主动延误求医凑菜单；普通关键节点较容易成功，失败多数还能接着过。

依赖：目录口径先确定。删一个选项时必须同批处理独占阶段、flag读写、死因、成就和提示，不能先上线缺半套的配置。

### 批次三：人生阅读不断裂，重开保持简单

范围：

- 03的同实例故事合并、旧年份折叠、自动检定行内呈现、真实近期事业提示。
- 04的新传承入口只留五属性+1，保留旧数据解释、预留和恢复流程。
- 图鉴简单筛选、可选一个想看的经历；结算用真实日志回顾，不新增在线生成或任务奖励。

交付结果：一年不会因一个事件拆出多张重复正文；玩家能快速看结果，想看骰子细节仍可看；再次开局的奖励和目标不需要学习新系统。

注意：这一批会碰会话、渲染和恢复边界，比单纯改文案风险大。日志关联若无法可靠补齐，旧记录独立展示，不猜因果；存档不兼容时明确提示，不擅自继续。

### 批次四：修明显矛盾，清长局复读

范围：

- 04列出的幼年成人职责、旧子女出生/存活/成长约束逐事件修补。
- 01指定的宗祠书虫重复次数；02里的粮铺改日、留货等弱后续先做文字与呈现减法。
- 六件家当连续读稿，去掉反复免责声明和同义结果，加入少量自然口语与网络表达。
- 同步正式规范和README的现状说明，不改写历史验收记录。

交付结果：没有一眼可见的年龄或关系漏洞；长局允许平淡生活，但不靠同一句反复出现填充。

暂不做：拆掉整个后期调度、重写家庭状态机、新增多个朝代、批量扩事件、寿命加速结算。弱后续如果仅靠显示就能解决，不动窗口和分组。

## 4. 轻量验收：只卡大问题，不考文案作文

### 必须挡住的问题

- 内容格式、引用、阶段、规则或正式测试失败。
- 玩家点了未提示的重大消耗/死亡；没有选择却自动承担新增主动冒险。
- 选择预算被重置、额外发传承、重复授奖、原存档被静默覆盖。
- 图鉴把确定不可达的项目当必收目标，或把旧死亡奖改成新的欢乐奖。
- 同一孩子刚出生就成婚、死者重新按活人行动、幼童无解释承担成年独立职责。
- 选择内容被按钮盖住、重要风险看不到、正文被裁、按住推进跨过待选项。

### 不作为硬性不通过

- 有人更喜欢某一件家当；某些安全选项更受欢迎。
- 某条日常没有笑点；某局普通、清贫或没有稀有成就。
- 长寿人生后段没有新菜单；一局超过两分钟。
- 六条路线死亡率、属性收益或高光率不相等。
- 正文超出软字数目标，但仍清楚好读。

对这些现象先读具体人生、听玩家反馈，再决定是否修改。不能为了指标增加暴毙、奖励、菜单或空洞新事件。

## 5. 必须执行的工程检查

以下是后续命令，不是本次已运行结果。项目使用Node内置测试，按当前`package.json`执行，不照抄旧文档的Vitest/Cocos命令。

### 生产内容有变化的批次

整批合并完成后各运行一次；仓库规定内容字段变化也包含纯文案修改：

```bash
npm run validate:content -- --content assets/resources/data/ming_end
npm test
```

检查生产引用、语义、内容指纹以及正式测试。不要把`local/`历史快照中的测试混进当前正式套件，不修改指纹去让旧档强行通过。

### 客户端或类型变化

```bash
npm run typecheck
```

合并客户端改动后执行一次，并在实际Canvas验证所改页面。整轮准备交付Web/微信产物时再各构建一次：

```bash
npm run build
npm run build:wechat
```

构建成功不是设备验收。没有微信开发者工具或真机证据时，交付记录必须保留该限制。

### 数值、触发或预算变化

优先复用现有`dice-rules`、`modern-budget`、`late-life`、`family-timeline`、`meta-loop`和存档行为测试。新回归只覆盖实际变化和现有缺口，不写“文件里含有一句话”“按钮存在”等替代用户行为的断言。

六卡共同数值和触发完成后，使用现有仿真一次跑四策略各100局，作为流程与预算检查，不作为趣味打分：

```bash
npm run simulate -- --samples 100 --out local/simulation/casual-final-20261118
```

`--out`必须使用新的未占用前缀；该工具拒绝覆盖已有结果，不能删旧证据后重跑冒充首次通过。后续日期不同应更换前缀。

需要针对某卡查分支时，可用已存在的参数，例如：

```bash
npm run simulate -- --samples 8 --strategy normal,cautious,risky,career --target-card CARD_MODERN_CORN --out local/simulation/casual-corn-20261118
```

定向卡样本不是自然抽卡概率，也不替代所有年龄边界。检查命令拒绝、非正常结束、最多5次选择、后续窗口和新增不可达项；第十年出现可见过程后仍无选择应报错，此前自然死亡且无选择的情况单独统计，不硬定“老死必须多少”“每几年必须发生大事”。如果命中失败，读具体日志并修原因，不仅增加种子寻找一条好看的。

## 6. 少量真人试玩怎么做

找3—5位没有参与配置的玩家，每人先自然玩一局；愿意继续的再换一件家当。人数用于早发现问题，不当统计显著性或留存预测。不需要先给完整规则课，不教最优选法。

观察时只记几个地方：

1. 选卡后，能否用自己的话说出想看什么，而不是只记得“+1”。
2. 第一次重大选择，是在想选哪个，还是在读规则读烦了。
3. 第一次失败后，是觉得有点倒霉但还能玩，还是不知道为什么被罚。
4. 什么时候开始连续按住；是主动想快看结局，还是不想再读。
5. 结束后能否想起一件具体遭遇；是否愿意换个家当再看。

只问：“哪句没看懂？”“哪段想跳过？”“刚才为什么选这个？”“下局想试什么？”不要用“是不是更有趣了”引导回答。

目标不是人人理解D20，而是大多数试读者不用解释就知道选项的主要动作与风险。记录原话和发生位置；网络梗若有人不懂，先看去掉它是否仍能理解，再考虑换成大白话。

## 7. 必要场景清单

这是跨批合并后的检查清单，不要求每次改一个字都重新走全套，也不宣称一组样本覆盖全部可能。

| 场景 | 看什么 |
| --- | --- |
| 六件家当各一段自然或合法换卡人生 | 各自卖点清楚，普通路线可玩，不全是道具警告 |
| 3岁、少年、成年人、65岁；早年份与1643/1644晚年份 | 行为适龄；有方向可选；同年快进不重复成长，不把开局晚当高龄 |
| 贫困、富足、体弱 | 不自动付无力承担的大成本；不同生活不被写成道德好坏 |
| 玉米稳妥/推广失败/送种涉险；手电结伴失败/自愿追贼；医药交药 | 成本风险、真实效果和提示一致，死因只来自仍保留的合法路径 |
| 普通黑屏误会失败 | 不再突然死亡，不触发旧死亡成就，仍有实际小损失 |
| 同事件多阶段、同ID跨年重复、长寿旧年回看 | 合并不丢结果、不串年，滚动不被强拉回最新 |
| 正常终局、早死、旧版简表记录 | 三段回顾只引用真实经历，素材少时不凑；图鉴与传承不重复领取 |
| 新资格、旧extra_card、pending可确认/不可确认、损坏槽 | 资格不吞、不多发、不篡改旧人生，错误提示能指向下一步 |
| 360×640与390×844实际Canvas，短横屏补查 | 字和按钮能读能点；选项风险可滚动看到；折叠和返回可操作 |
| 按住推进时松手、打开管理、后台、待选、死亡、保存失败 | 立即停止连续授权，恢复保持暂停，不补跑 |

微信端另查真实触屏拖动、系统后台、字体、安全区及存储。Web鼠标或CDP模拟不能写成微信真机通过。

## 8. 正式文档同步与交付记录

实施时按[总纲](00-总纲与修改清单.md)列出的现有规范同步修改，不另留互相矛盾的规则：

- 文案规范明确允许少量网络梗、减少重复告诫，保留清楚的因果和风险。
- 制作文档对应段落同步轻休闲定位、当前Canvas架构及新分支，不全篇清洗历史记录。
- 家当制作说明及提示同步新门槛、新奖与停用路径。
- README只写已经完成并实际验收的功能和限制。
- 已安装技能中的旧高门槛、强制段子配额不作为本轮加戏依据；若后续正式修改技能，单独遵守技能维护流程，本轮不自动修改工具规则。

每批交付只需一张真实清单：改了哪些ID/文件、是否改规则、跑了什么及结果、实际看了哪些页面、还有哪些设备没测。不要用几千字“完成总结”代替一次真实游玩，也不要把本方案中的概率表写成新版本留存或平衡结论。

完成标准：该批承诺的修改完整落地，工程检查通过，实际页面能读，明确的大漏洞消失；文案允许有个人口味差异。若玩家主要仍被某一段拖住，回到具体段落做减法，不再扩一套系统解决。
