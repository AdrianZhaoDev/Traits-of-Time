# 《穿越了这次我带大喇叭逆袭》 · Layout 独立客户端

本仓库是独立的 Web / 微信小游戏客户端。界面使用 npm 发布版 **minigame-canvas-engine 1.0.29** 的 XML、Flex 布局与 Canvas 元素；不是 DOM 游戏界面，也不是微信 WebView。游戏核心、生产内容、媒体和构建工具均位于当前仓库内，不依赖上级目录、已删除的 Cocos 工程或 V2 工程。

## 环境与安装

需要 Node.js **22.22.1 或以上**。本工程锁定 TypeScript 5.9.3、Vite 7.3.1、esbuild 0.28.2；使用提交的 `package-lock.json` 安装：

```bash
# 在当前仓库根目录执行
npm ci
npm run dev
```

只需安装这一个 `package.json` 的依赖。原游戏内容校验器使用 `ajv`；当前人生存档使用 `fflate` 0.8.3 的同步纯 JavaScript DEFLATE 实现，许可见 `licenses/fflate.MIT.txt`。不需要到上级目录安装依赖，也不需要恢复旧工程目录。

## 开发与 Web 发布

以下命令都在当前仓库根目录执行：

| 命令 | 用途 |
| --- | --- |
| `npm run dev` | 校验本地媒体，然后启动 Vite 开发服务器；许可由根目录 `licenses/` 提供 |
| `npm run build` | 校验媒体并生成 `dist-web/` |
| `npm run preview` | 预览已经生成的 `dist-web/`，需先运行 build |
| `npm run typecheck` | 校验媒体并执行 TypeScript 检查，不生成 JS |
| `npm run build:wechat` | 校验媒体并生成原生 Canvas 小游戏 `dist-wechat/` |
| `npm run prepare:assets` | 校验 `public/` 必需媒体，不删除或重建媒体源 |

Web 入口为 `index.html` / `src/main.ts`。将 `dist-web/` 作为静态站点目录托管；`base: "./"` 支持部署在子目录。请通过 HTTP(S) 访问，不要直接用 `file://` 打开源码或产物。所有图像、音频与特效都是包内相对资源，不依赖媒体 CDN。

开发服务器不监视 `local/` 实验与验收产物目录，避免遍历其中的工程副本或 Windows 目录链接导致 WSL `readlink EINVAL`。正常 `src/` 源码仍参与热更新；修改 `local/` 下的预览文件需手动刷新。

## 微信开发者工具导入

1. 运行 `npm run build:wechat`。
2. 在微信开发者工具选择 **小游戏**，导入当前仓库的 **`dist-wechat/`**，不是仓库根目录或 `dist-web/`。
3. 生成的 `project.config.json` 默认使用 `touristappid` 供本地导入；体验、上传及发布前，必须替换为自己的真实小游戏 AppID。每次重新构建都会重新生成该配置，请在新产物中再次设置真实 AppID。
4. 使用支持 `wx.loadSubpackage` 的基础库。工程配置为 3.4.9；正式上线应在目标基础库与真实设备上验证。

产物包含真实 `game.js`、`game.json`、`project.config.json` 和 CommonJS 游戏程序，不包含 WebView。`src/wechat.ts` 只导出 `startWechat()`；主包先安装微信环境缺失时所需的**纯数据 `structuredClone` shim**，再加载分包，最后调用该入口，因此共享引擎不会先于 shim 执行。Web 不安装或覆盖 `structuredClone`。

### 包大小与资源分包

主包只保留启动代码、配置和许可声明；以下四个普通分包通过 `wx.loadSubpackage` 加载成功后才启动游戏：

- `runtime/`：`application.js`，由共享引擎、原始内容导入和 Layout 客户端一起打包。
- `media/art/`：品牌头像与八件实际使用的原始物品图；A 首页品牌图形由程序绘制。
- `media/audio/`：音乐、环境音、提示音三个通道所用的原始 MP3。
- `media/fx/`：四张原始像素特效图集与 `data.json`。

每个分包目录都有小游戏协议要求的 `game.js`。构建会输出主包、各分包及总包的实际字节数；主包及每个生成分包均采用 **4 MiB** 保守上限，总包上限为 **30 MiB**。超限立即报错并删除本次不合格输出，不会把超限目录当作可发布结果。普通分包的微信官方限制可见[分包加载文档](https://developers.weixin.qq.com/minigame/dev/guide/base-ability/subPackage/useSubPackage.html)；本工程对每个分包额外使用同样的 4 MiB 门槛。

## 源码与目录约定

`src/` 使用本项目内的 `./game/...` 模块：

- `src/game/application/GameSession.ts`：人生推进与所有待选决策的权威入口。
- `src/game/application/StaticContentLoader.ts`：直接导入 `assets/resources/data/ming_end/` 的生产 JSON。
- `src/game/core/`：游戏规则、检定、事件、事业、存档数据与内容校验。
- `src/game/presentation/`：保留纯 TypeScript 的枚举翻译、日志解释与完成记录，不含 Cocos 组件。

这些模块来自原游戏的实际运行源码并由本项目维护。当前项目不导入 `cc`，也不在启动或构建时从 Git、旧目录或旧构建包恢复依赖。珍宝与成就仍只来自真实生产内容和游戏日志。

家庭与个人人生扩展追加生产内容；原预算修复及历史仿真见 [家庭内容交付](Doc/家庭内容交付.md)。本轮后半生按真实家资、身份、事业与关系继续发展；生产事件及内容指纹按实际数据更新，不绕过旧档匹配。前述旧版验证不代表本轮通过。

### 后半生与重大选择

开局算第一年，`years_elapsed >= 9` 进入境遇兑现；`>= 14` 进入结果扩大，`>= 19` 且年龄达到 55 才进入晚景定形。第十年不是年龄判定：少年不会被称作老人。富贵显达、富足自在、位高望重、清贫有名、困顿失意、晚景艰难之外仍有普通生活；真正的权势依当前身份而非单看人脉。路线使用保留阈值和连续三年候选防抖，当前事件仍核对实际财富、身体、身份与家庭状态，已取得的事业和关系不会因为转线抹去。

每年照常结算，历史及事业之后、随机事件之前最多处理一组到期后续；后续不占日常随机额度。内容为关键安排指定相对后期起点或前序兑现年的最早、最迟窗口；前提失效时有不擅自选择的收束。未用事业转向且适用的角色可以在后续窗口真正选择读书、学艺或原地转向，已经使用机会的角色继续已授权的人生；不会自动接事业、支付大额费用或代选。原生和家当剧情共享最多 5 次重大选择，终点不统一推迟到某一年。本轮后期不跳年、不合并流年；既有晚开局在同年发生的多个历史节点仍保留。

后续剧情、六件家当的实际前置、逐路线人工阅读样本及指标口径见 [家庭内容交付](Doc/家庭内容交付.md#本轮后半生内容与待验收)。本轮候选的四策略、定向场景、内容校验、测试、类型检查、两端构建与实际 Canvas 验收均以独立验收记录为准，此处不预写通过。

### 玩家功能

- 首页、随机身份揭晓、正权重开局池加权无放回抽取至多三件候选；确认前可免费反复替换任一候选，最终只带一件家当。旧人生的定向家当传承仍占一个候选位置并可免费更换；候选草稿可保存，恢复后仍需确认。
- 纪年与身份 HUD、五维属性、全宽折页历史，以及顶部随身物品图标与详情。
- 历史按年份折叠，展开后保留实际发生的选择、检定和结果顺序；当年记录与存档仍逐年保存。检定计算详情按需展开，默认呈现属性、成功率与必要风险。
- 重大选择的可用状态、消耗、风险与概率；自动检定和当年剩余事件仍由原 `GameSession` 处理。
- 点击推进一年，按住连续推进；自动检定后继续，遇到玩家选择、终局、后台或取消触摸时停止。
- 事业、家当、生涯成就管理；选中并确认退出事业，返回后保留未完成的选择。
- 终局按真实开局、经历和结局三段回顾，再展示身份、最终属性、事业与成就；资料不足时不编造经历，可返回历程、重启或返回首页。
- 音乐、音效、环境声独立调节和静音；当前人生、完成记录与音量分别保存在本机。
- 人生图鉴按已核实可获得的成就与死因计算收集率；不可获得、待核实和旧版未知 ID 单独展示，不计入当前完成度。可按状态与已核实家当筛选，选一个有可靠提示的目标，仅作提醒，不更改事件或奖励。结算类成就只记录最终称号。维护证据见 [逐 ID 目录核查](Doc/轻休闲体验优化方案/图鉴逐ID核查.md)。
- 每完成一局获得一次下局传承：五属性任选一项开局 +1，受上限限制、不累计。取消不消费，确认开局并保存后才消费；旧人生的 `extra_card` 继续按旧语义读取，不补发属性。
- Web 具有同步的无障碍控件、键盘操作与模态焦点约束；原生微信界面不依赖这些 DOM 控件。


本目录的职责划分：

- `src/controller.ts`、`src/presenters.ts`：无 DOM 的会话编排、遮罩栈、真实日志与选择说明。
- `src/view.ts`、`src/ui.ts`：使用 Layout XML / Flex 构建全部屏幕，不复制 HTML 游戏界面。
- `src/home.ts`：A 首页三段标题、四个真实入口与进度警告；缓存绘制简化红色喇叭，不再加载旧夜景或播放轻尘。
- `src/renderer.ts`：两棵 Layout 树、顶层输入路由、滚动、长按、键盘及特效合成。
- `src/platform.ts`：Web / 微信主 Canvas、离屏 Canvas、图像工厂、视口、安全区、存储与前后台事件。
- `src/audio.ts`：三通道音量、手势解锁、Web Audio 元素 / 微信 `InnerAudioContext` 适配。
- `src/effects.ts`：原图集逐帧回放，由宿主每帧合成，没有额外动画循环。

- `tools/build-wechat.mjs`：原生小游戏打包、分包配置和包大小门槛。

## 存储边界

当前人生使用独立的 `time-travel.current-life.a.v1` / `time-travel.current-life.b.v1` 双槽。格式 2 将完整 `SessionSave` 无损去重并压缩为 `dedupe-deflate-base64`，封套带代次、校验和及人生标识；解压中间数据和完全展开的数据各限 32 MiB。旧格式 1 仍可读取，后续提交使用格式 2。每次提交初始化、换候选、候选选中草稿、选家当、剧情选择、检定或推进时同步保存并回读确认，写入新槽时保留上一份有效槽；无需依靠切后台事件。旧会话光标没有草稿字段时按未选恢复，不改变既有候选。启动后可继续或确认重开；恢复时暂停，不自动执行下一步。读档验证内容指纹、规则实现版本、完整命令和确定性回放；新槽损坏时尝试上一份有效槽。不兼容或无法读取的原档不会被静默清除，重开前会明确提示覆盖。存储读写失败会停止推进，并可在修复存储后重新读取；不能将未确认的操作视为已保存。

已完成的人生记录经 `LifetimeRecords` 单独保存；音量沿用 `time-travel.audio-settings.v1`。Web 使用同源 `localStorage`，微信使用同步平台存储。两端不互通；清站点数据、换域名或清小游戏数据会移除相应数据，也没有云端同步。音量写入失败时仅在本次运行生效，并在控制台如实提示。完整会话包含重放记录，两个槽通常各占一份压缩空间；大小及同步压缩、回放校验耗时随人生长度增长，具体上限取决于平台容量与设备性能。

图鉴与传承共用原 `time-travel.lifetime-records.v2` 键，当前载荷版本为 3，包含完成记录、资格来源和传承提交状态。读取旧 v2 载荷保留既有资格；首次读取旧 v1 记录时保留成就与统计，未知旧死因标记为未记录，有旧完成记录赠送一次资格，不按历史局数累计。下次发生记录或资格写入时转为 v3，保留 v1 原值；较新记录损坏时不回退旧 v1，也不覆盖损坏数据。图鉴计数只包含当前目录中的 ID。

收集目标另存 `time-travel.collection-goal.v1`，不是人生或成就记录；保存后回读确认，读取或写入失败只提示目标未确认，不阻塞人生。目标在新版本不再可追时保留并可清除，只读页面不修改目标。

图鉴记录及传承写入均需回读确认；失败时停止推进并提示重新读取。传承开局先以新人生标识预留资格，当前人生保存成功后再确认消费；重启恢复先读取两处数据，只有能确定对应人生是否已保存时才提交或释放预留。若回退的人生不是预留目标，且槽损坏、版本不兼容或读取不可用，无法判断新人生是否曾保存时会保留待确认状态并禁止推进或覆盖，不自动退还；可先修复存储或恢复原槽后重试。如果无法恢复，玩家可在失败页二次确认永久放弃这一次传承，不补发、不删除人生槽；之后重开仍须另行确认覆盖。已保存的终局会在续局或覆盖前幂等记录。两处存储不是原子跨键事务，恢复协议依赖平台单键 `setItem` 原子性。引擎人生存档为 v6，规则实现版本为 4；v5 旧档先报 `SAVE_VERSION_MISMATCH`，同存档版本而规则旧时为 `RULES_MISMATCH`。旧人生档不迁移、不篡改指纹或自动覆盖，保留并提示不兼容。

Web 使用同源 Web Locks 在读取、恢复及整个游戏会话持有独占写锁；其他标签页只读，可看已完成人生和记录但不能开局、续写或重开。关闭持锁页后刷新另一页以取得锁。没有 Web Locks 时也进入只读模式；请使用支持 Web Locks 的浏览器，通过 HTTPS 或 `localhost` 访问，普通局域网 HTTP 地址通常不是安全上下文，可能无法开局。锁不跨不同浏览器或设备；微信端按同一小游戏单实例运行，设备间不互通。

容量与耗时仅为本地内存模型实测，不是设备验收：Node 22.22.1、WSL2、i7-12700F，以下为完整双槽封套，UTF-16 包含槽键名但不含其他存储项或平台额外开销；同步编码、解码及确定性严格恢复会随历史增长而变慢。

| 样本 | 单槽 UTF-8 / UTF-16 | 双槽 UTF-16 | 编码 / 解码 / 严格恢复 |
| --- | --- | --- | --- |
| seed 29，56 年 | 79,102 / 158,204 B | 316,524 B | 173.5 / 31.4 / 715.5 ms |
| seed 55，97 年 | 118,886 / 237,772 B | 475,660 B | 253.8 / 37.5 / 1,232.8 ms |

两例通过 1 MiB/键、10 MiB 总量的保守内存模型和浏览器 5 MiB UTF-16 总量模型；1 MiB/键只是保守代理，非对小游戏官方单键限制的断言。未预留其他键、平台开销或代表真实微信设备表现；实际受配额、性能及可用空间限制。

## 音频与像素动态

- `GameAudio.unlock()` 必须在真实点击 / 按键回调中同步调用。未解锁前不会播放音乐或提示音。
- 复用原 MP3：3 首音乐、3 路地区环境音、7 种当前有调用的提示音。两路循环播放器与 4 个复用提示音声部限制并发；滑块值保存在原 0–1 范围，并在播放器边界采用平方增益。
- 切到后台会暂停循环并停止提示音；返回前台仅恢复当前音乐 / 环境音，不补播过时提示音。微信遵循设备静音开关；文件不可用时保持静音，不生成替代声。
- `PixelEffects.draw(context, width, height, now, active)` 由宿主在基本界面和顶层弹窗之间调用，`now` 使用毫秒时间戳、尺寸使用逻辑 Canvas 单位（标准宽 750），DPR 缩放由宿主负责。
- 烛火位于左下、202 逻辑单位高的底栏上方；金币中心位于逻辑坐标 `(263, 212)` 的家资附近，poof / confetti 位于中央。四张图像只加载一次，逐帧从原图集中裁切，无每帧创建图像或像素缓冲。
- 非活动界面与后台停止推进特效时钟；可用的 `prefers-reduced-motion` 系统偏好会保留静态烛火并关闭一次性动画。
