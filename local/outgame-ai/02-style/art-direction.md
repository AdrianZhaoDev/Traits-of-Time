# A「爆笑开播」美术执行说明

**状态：用户已选定 A，作为《穿越了这次我带大喇叭逆袭》的全项目风格。** 本文件直接用于制作，不再征集其他方向。视觉的唯一规范是 [UI 整体风格方案](../../../Doc/UI整体风格方案.md)；动效遵循 [动效与微交互制作规范](../../../Doc/动效与微交互制作规范.md)，文字遵循 [文案设计与风格规范](../../../Doc/文案设计与风格规范.md)。

风格批准不等于客户端已经换肤，也不等于新增素材、批量生产、参考上传或收费服务已经授权。本次为文档覆盖修订，不改运行代码、生产 JSON、内容 ID、概率及持久化。

## 1. 唯一视觉目标

**明亮的明朝市井穿越喜剧，像一张有劲儿的漫画开场海报。** 奶油纸底、番茄红标题、亮黄主按钮、深墨字；局部粗轮廓与短硬投影带来轻快感。不是暗色水墨、暮光小院、宫廷卷宗、仙侠传送门或霓虹界面。

- 首页允许完整大标题、喇叭轮廓和少量错位套色；一屏只有一个主视觉锚点。
- 其他页面沿用同一色板、字阶、按钮和线条，不复制首页整套海报。长文、列表、风险决策主要依靠平整纸面、留白和分隔组织。
- 终局收敛夸张：不在死亡、灾难或遗憾结局上放拟声字、礼花或嘲弄性表情。
- 颜色与状态值只引用整体规范的命名 token，不建立本目录的另一套色板。主行动是 `sun` 底配 `ink` 字；`accent` 是标题、品牌及必要警示，不替代所有主按钮。

## 3. 光线、材质和边缘

- **光线：**以平光、日间亮度和清楚色块为主。器物需要体积时统一采用左上轻光，禁止强聚光、炫目反射或扫过正文的光束。
- **纸面：**暖而明亮、低噪点；正文底近乎纯色。纸纤维只在边缘或少量空白处，不做黄旧污渍、撕裂堆叠或仿公文质感。
- **器物：**形状先于纹理，色块先于写实。普通衣物、民居和生活工具保持明朝市井尺度；现代物品保留真实轮廓，不擅自添加能力、装饰配件或品牌字样。
- **墨线：**主视觉和关键交互可粗；文字清单使用细分隔或无外框。不能把每行列表、每段说明都套厚黑框。
- **阴影：**只在主要按钮或少量重点纸签上使用单方向短硬偏移，不用柔光、浮雕、金属包边或多重投影。按下时压低投影，命中区不随绘制位移移动。
- **密度：**装饰退到标题旁、边缘和明确的插画区。风险说明、数值、长标题及操作按钮后面不能有墨线、图形或亮斑穿过。

## 4. 字体、阅读与布局

标题和按钮用粗重、正体的中文无衬线，正文用清晰无衬线；系统字体回退以整体规范为准，不下载未授权字体。首页优先按下列节奏分行，完整游戏名不得截断：

```text
穿越了
这次我带
大喇叭逆袭
```

核心说明为“带上一件现代物品，去明朝过一生。”，保留“我要穿越／声音／成就／统计”四个入口及“本局进度仅临时保留，关闭或刷新后不能继续。”的完整提示。所有文字、数值、状态与按钮均由程序绘制，不烘进图。

750 为逻辑宽，不是 CSS 宽或图片分辨率。按实际 Canvas CSS 矩形换算字高、行宽与命中区；正文以约 16 CSS px 或以上为阅读目标，可操作目标至少 44×44 CSS px。普通文字对比至少 4.5:1，大字和有意义控件边界至少 3:1；装饰分隔色不得冒充可交互边界。最终以合成后的实际画面验收，不用单个色值代替对比测量。

短屏先缩小插画与空白，再允许正文滚动，不挤掉出口、提示和可操作高度。长屏增加舒展留白，不把主行动推离首屏。终局、管理、历史和选项必须能完整读到最后一条。

## 5. 背景与切图

- A 的平整纸色、几何底形、线条和按钮由程序原生绘制即可；不为凑素材数量强制生成整幅场景。
- 如使用 `IMG-BG-01..05`，它们只提供无字的纸面、边缘市井剪影或独立插画。阅读中轴保持平静，不预画按钮、字标、状态框、数字或裁切标记。
- 目标背景母版为 1080×1920，但原服务输出按真实尺寸／格式留存。背景等比 cover 或在授权范围内补边，禁止宽高分别拉伸；独立器物按 contain 保持完整轮廓。
- 生成图片的中央约 60% 宽、65% 高可作为初始构图安全范围，不代替长短屏实测。需要重排的标题、按钮和警告始终属于 Layout，而非图片的一部分。
- 缺图时使用 `paper`／`surface` 与程序原生文字控件；不依赖素材成功加载才可操作。启动加载和失败提示保留可靠宿主兜底。
- `public/art/scenes/home.png` 不作为 A 风格参考，不必按它的场景、色彩或门环继续制作。

## 6. 全项目落位与实现隔离

首页、身份、家当、本机成就、统计、声音、管理四页、物品详情、终局，以及人生推演、HUD、历史折页、博古架、推进、重大抉择与检定的目标规范，统一由整体方案定义。

本阶段只修文档。局外制作任务仍仅处理其 screen／overlay；从局内打开的管理、设置与详情只改变弹层，底下人生画面保持原样。局内画面、原烛火／金币／死亡／成就 FX、局内音乐与地区声不能因“全项目风格”被顺带替换；真正实施须属于明确的界面任务。

实际宿主为 TypeScript + minigame-canvas-engine 1.0.29、XML／Flex、Canvas、Web／微信小游戏。HTML 仅供风格参考，不迁移成 DOM 游戏，也不使用 Cocos API。

## 7. 动态与声音

动作像纸签落稳、按钮压下：短、利落、可中断；不要求持续尘埃、灯光扫描、视频、镜头推进或转圈传送门。装饰不消费游戏随机数、不延迟命令、不锁住操作等待表演；减少动态时取消位移、缩放和循环装饰，保留同样的最终状态与操作。

首页及开局新音乐的目标为明亮、温暖、带一点俏皮的短拨弦／木质动机，给阅读留空间；终局同主题收敛，不用悲壮轰鸣或滑稽死亡音。现有音频不因规范更新自动替换。新增音乐、音效及任何参考上传仍须先有明确供应商和预算／额度授权；未生成、未试听的条目不能写成已验收。
